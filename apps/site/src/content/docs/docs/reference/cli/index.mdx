title: "The smthrs command"
description: "Global flags, verbs, aliases, and exit codes of the smthrs command line."
---

`smthrs` is the command line of the Smithers control plane (`smithers` is an alias of the same executable): it plans, approves, and runs durable flows, and inspects what ran.

## Global flags

Every verb accepts these flags.

| Flag | Value | Description |
| --- | --- | --- |
| `--credential` | token | Bearer token for the remote control plane; falls back to `SMITHERS_API_KEY`. |
| `--json` | none | Print the machine-readable document instead of the human rendering. |
| `--remote` | URL | http(s) URL of the control plane to act on; falls back to `SMITHERS_REMOTE`. |
| `--quiet` | none | Suppress banners and progress on stderr; stdout documents still print. |
| `--mcp-config` | path | Path to the JSON array of MCP servers the local executor projects into a run's flow catalog. |
| `--root` | path | Project root to act on, instead of walking up from the working directory. |
| `--backend` | name | Hidden. `sqlite` is the only supported value, so it is a no-op; any other value exits 1 with `unsupported_database`. |
| `--version` | none | Print the installed version. |
| `--help` | none | Print the help document. Neither this nor `--version` resolves a project or opens a database. |
| `--completions` | shell | Print a shell completion script. |

## Aliases

Alternate spellings the parser accepts. They are hidden from `--help`, which lists the canonical surface.

| Alias | Canonical form | Notes |
| --- | --- | --- |
| `resume <run-id>` | `run --resume <run-id>` | |
| `workflow list` | `ls` | Every other `workflow` subcommand was removed in 1.0. |
| `inspect [run-id]` | `status [run-id]` | |
| `why [run-id]` | `status [run-id]` | |
| `events [run-id]` | `logs --json [run-id]` | |
| `gateway` | `serve` | `gateway status` and `gateway stop` were removed in 1.0. |

## Exit codes

`smthrs` uses one status vocabulary, so a script can branch on it.

| Code | Meaning |
| --- | --- |
| `0` | The command did what it was asked. |
| `1` | The command failed, or the run it reports settled `failed`. |
| `2` | The invocation was wrong; the message names the flag or argument. |
| `3` | The run is parked at `waiting-approval`; answer it with `smthrs approve` and resume. |
| `130` | The run was cancelled or interrupted (SIGINT). |
| `143` | The run was terminated (SIGTERM). |

Codes 3, 130, and 143 report a run outcome rather than a failure of the command, and are decided from the control receipt alone.
