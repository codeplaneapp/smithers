Patch release: declare the missing `@mdx-js/esbuild` runtime dependency
in `smthrs` so a fresh `bunx smthrs init`
can actually start the CLI.

---

## Fixes

- **`smthrs` now declares `@mdx-js/esbuild`** as a direct
  dependency. `src/mdx-plugin.js` imports `@mdx-js/esbuild` but the
  package wasn't listed in `packages/smithers/package.json`, so a clean
  `bunx smthrs@latest init` produced an unresolvable
  `Cannot find module '@mdx-js/esbuild'` as soon as the CLI loaded
  (`@smthrs/cli` re-exports `mdxPlugin` at startup).

## Features

- **`bunx smthrs gui [path]`** opens a directory as a workspace in the
  Smithers GUI macOS app (via `open -b com.smithers.SmithersGUI`). A bare path
  argument (`bunx smthrs .` or `bunx smthrs <dir>`)
  is treated as `bunx smthrs gui <dir>`, matching the `code .`
  convention from VS Code / Cursor.
