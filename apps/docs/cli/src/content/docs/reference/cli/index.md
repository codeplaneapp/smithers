## The canonical pages are on smithers.sh

The reference for each `smthrs` verb lives at `/cli/<verb>`, on smithers.sh.
Those pages carry the arguments, flags, output, exit codes, and the verbatim
`--help` capture for every shipped verb, and they are generated by
`apps/site/scripts/gen-cli-data.mjs` from the real Effect CLI parser, from
`Verb.ts`, and from `Unsupported.ts`. A help string, a removed-command anchor,
or a version bump moves them, so they cannot drift from the binary.

Start at [the CLI reference index](https://smithers.sh/docs/reference/cli/), or go straight to a verb:
[`plan`](https://smithers.sh/docs/reference/cli/plan/), [`run`](https://smithers.sh/docs/reference/cli/run/), [`up`](https://smithers.sh/docs/reference/cli/up/),

## What the pages under this directory are

This package also carries source-generated reference pages for three verbs:
[`smthrs plan`](/reference/cli/plan/), [`smthrs run`](/reference/cli/run/), and
[`smthrs up`](/reference/cli/up/).

They are written by the package's own documentation pipeline, declared in
`PACKAGE.ts` as the `referenceCliPlan`, `referenceCliRun`, and
`referenceCliUp` targets. Each one reads `packages/smithers/src/**`, this
package's `README.md` and `docs/`, and the captured `--help` output, then
regenerates its page and runs the package typecheck as a gate. They exist to
prove that a verb reference can be derived from the source, and to catch
places where `--help` and the parser disagree.

They are not ingested into smithers.sh. When one of these pages and the
smithers.sh page for the same verb disagree, the smithers.sh page is the one to
follow, because it is the one the binary generates.

`plan` requires a flow id. Omitting it with terminal stdin opens the flow
picker; with piped stdin it exits 2 and names `flow-id` and `--wizard`.
`--remote` is a shared global flag, listed under "Global flags" on these pages.
