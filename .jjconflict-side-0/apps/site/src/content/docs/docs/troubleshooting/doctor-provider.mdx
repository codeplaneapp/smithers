---
title: "doctor reports a provider problem"
description: "Fix provider credentials that the smthrs doctor providers check warns about."
---

## Provider readiness warns or fails

```text
$ smthrs doctor
smthrs doctor: /work
…
warn providers: no provider key set (OPENAI_API_KEY exported but empty)
```

**Cause.** The seat's provider key is unset, or exported but empty (an exported-but-blank variable reads exactly like an unset one). The `providers` check reads `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `OPENROUTER_API_KEY`, and `CEREBRAS_API_KEY`. A `warn` stops nothing by itself, but the next launch whose seat names that provider resolves no seat, and the executor declines the launch.

**Fix.** Export the key for the seat's provider:

```bash
export OPENAI_API_KEY="<key>"
```

For `openai` seats, `SMITHERS_OPENAI_AUTH` selects how the seat authenticates: `api-key` or `chatgpt`. With `chatgpt`, the ChatGPT session supplies the OpenAI credential, and doctor notes it on the providers line.

**Verify.** `smthrs doctor` reports the providers check `ok` and names the key you set. Warnings alone exit 0; any `fail` check exits 1, with the full report printed first.

## CEREBRAS_API_KEY is set but no seat uses it

```text
$ smthrs doctor
smthrs doctor: /work
…
ok   providers: CEREBRAS_API_KEY
```

**Cause.** Doctor reports `CEREBRAS_API_KEY` like the other keys, but the seat resolver has no route for the `cerebras` provider, so a `cerebras:` seat fails at launch even with the key set. The key is present; the route is missing.

**Fix.** Declare the seat with a provider that has a seat route, and export that provider's key instead. [Model seats](/docs/guides/model-seats/) lists the seat strings and the keys they read.

**Verify.** The launch resolves its seat instead of failing on the `cerebras:` route. `smthrs doctor` still lists `CEREBRAS_API_KEY` as present; with no seat routed to it, that line is informational only.

## Still stuck?

Run `smthrs bug` with the symptom as the summary. [smthrs bug](/docs/reference/cli/bug/) posts the report with your CLI version, platform, and Node version attached, and everything passes through the journal's shared redaction rules before it leaves the machine.
