06 · Interpretation

What this run does—and does not—say.

The strongest conclusion is narrow: on this exact audited Valibot task, the Kimi-led rerun outperformed the recorded Opus-led baseline.

01

One task, one attempt

A 1.000 single-task result is not an estimate of K3’s 115-task resolved rate. More tasks and repeats are required for a stable model-level conclusion.

02

Scaffold attribution

Kimi handled three candidate roles; Codex GPT‑5.5 independently reviewed. The reviewer made no fixes, but the workflow itself may improve performance versus a single-agent scaffold.

03

Host-run threat model

The build container was offline and network tools were denied, but the agent was not under a complete OS-level host sandbox. Integrity therefore also relies on the clean command audit.

04

Patch capture caveat

The collector’s agent.diff includes only the two tracked barrel edits; Git omitted the 37 newly created untracked candidate files. The audit inventories those files, and the scorer compiled/tested the finished tree. Three additional __bench__ files in that inventory were injected only after the run by scoring.

05

Runtime is hardware-bound

The official linux/amd64 task image ran under emulation on an arm64 Mac. Treat 53m32s as this setup’s wall time, not a portable latency benchmark.

06

Baseline target identity

The old Opus report records the weight‑3 target plus one weight‑2 target passing, but not whether examples or ISBN was the miss. This report does not infer it.
