---
title: share-pack
description: Turn the current project's .smithers into a published workflow pack: validate the manifest, prepare the repo, push it to GitHub, and open the awesome-smithers PR.
---

`share-pack` completes the pack loop: create → run → **share**. It takes the
current project's `.smithers/` (every `.smithers` is a publishable pack) and
walks it through publication, one durable step at a time.

```bash
bunx smithers-orchestrator workflow run share-pack --input '{"dryRun":true}'
```

## Input

| Field | Meaning |
| --- | --- |
| `repo` | GitHub repository to create for the pack (`owner/name`). Optional; derived from the manifest when omitted. |
| `registry` | Override the awesome-smithers registry repository. |
| `dryRun` | Prepare and print everything without pushing or opening a PR (default `false`). |

## Stages

1. **validate-manifest**: loads `smithers.toon` from the pack root and fails
   fast on a malformed or incomplete manifest.
2. **prepare-pack**: assembles the publishable file set, excluding private
   state (databases, runs, logs, `node_modules`, executions).
3. **publish-pack**: creates and pushes the GitHub repository with the `gh`
   CLI.
4. **share-registry**: calls the same machinery as
   `bunx smithers-orchestrator share` to add the pack's entry to
   awesome-smithers and open the pull request.

Each stage is gated on the previous one, so a failed push can be retried
without re-validating, and a `dryRun` run shows the registry entry and diff
without touching GitHub. The run has a live UI (`bunx smithers-orchestrator ui RUN_ID`).

Requires an authenticated `gh` CLI; the workflow degrades with a clear error
when it is missing.
