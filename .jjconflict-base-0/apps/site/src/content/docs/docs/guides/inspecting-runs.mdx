Run state is durable, so every question about a run is a read: `ps` finds the run, `status` diagnoses it, `logs` replays its events, and `output` prints one node's recorded value. This guide walks the read path end to end.

## Before you start

- A project with runs. Any `smthrs up` or `smthrs run` launch writes one under `.flows/`.

## 1. Find the run

```bash
smthrs ps --flow deploy/status --status failed
```

`smthrs ps` prints one item per durable run with its run id, flow id, status, waiting reason, and timestamps. `--flow` narrows the listing to one flow id. `--status` narrows it to `accepted`, `running`, `parked`, `waiting-approval`, `cancelled`, `completed`, or `failed`; an unrecognized value is a usage error (exit 2), not an empty list. A run that has sat at `accepted` with no owner process past the launch handoff is labelled as waiting on an `executor`, which distinguishes it from a run a live process owns.

## 2. Read the diagnosis card

```bash
smthrs status <run-id>
```

The card is computed from the run's own journaled events and answers "what is this run doing, and what does it need": a `Verdict` line (the status plus the reason that best explains it, such as the journaled failure cause or the question a parked run is asking), a `Run` line (run id, flow id, seat, duration), an `Activity` line (turns, calls, refusals, duplicates, edits), a `Tokens` line, and up to three `Refusals` lines. When they apply, a `Cause` line, an `Output` line, and an `Unblock` line follow; a parked run's `Unblock` is the ready-to-paste `smthrs approve` and `smthrs run --resume` pair. Every card ends with a `Next` line pointing at `smthrs logs`.

The card is a read-only projection and never changes the run. An unknown run id prints `Run not found: "<run-id>"` on stderr and exits 2.

## 3. Follow the events

```bash
smthrs logs <run-id> --follow
```

Without `--follow`, `smthrs logs` prints the recorded history once as a turn-by-turn transcript: a summary header (run id, status, duration, turns, calls, tokens), one `=== turn N ===` header per model turn, and one offset-stamped line per event under it. A run with no events prints `No events.`. With `--follow` it stays attached and prints one line per event as the event lands, until you interrupt it. Omitting the run id reads the events of every run in the project.

## 4. Print one node output

```bash
smthrs output <run-id> result
```

Node ids are `<flowName>#<ordinal>`, the ordinal counting that flow's calls within the run from 1, and the reserved id `result` names the run's final assistant output. With no node id, `smthrs output` prints every recorded node in the order the calls started; a call that started and never settled is listed with outcome `pending`, which is what a run that died mid-call leaves behind. A node id that names nothing prints the ids the run does have and exits 2.

## 5. Script against --json

Every read verb prints a machine-readable document with `--json`. `ps` and `status` print the runs listing, `logs --json` prints the raw events (one compact document per event in follow mode), and `output --json` prints the node objects with `nodeId`, `flowName`, `outcome`, `input`, `value`, and `message`. For example, the node ids of every failed call in a run:

```bash
smthrs --json output <run-id> | jq -r '.[] | select(.outcome == "failure") | .nodeId'
```

## 6. Explain a run for an agent

An agent reads the same account through the MCP server. The `explain_run` tool explains what happened in one run: status, cause, turns, calls, refusals, and cost, plus the rendered diagnosis card, so a downstream agent can act on a run without shell access. [The MCP tools reference](/docs/reference/mcp-tools/) lists `explain_run` alongside `get_run`, `get_run_events`, and `watch_run`.

## Verify it worked

- `smthrs status <run-id>` exits 0 whether the run is red or green; the exit code reports the command, never the run's status. Read the `Verdict` line for the run.
- `smthrs logs <run-id>` ends the transcript with the run's settling events, and `--json` is the raw event stream, byte-stable for scripts.
