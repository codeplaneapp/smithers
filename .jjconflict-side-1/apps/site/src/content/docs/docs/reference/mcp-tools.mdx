`smthrs --mcp` serves the control plane as a Model Context Protocol server over stdio: newline-delimited JSON-RPC 2.0, protocol version `2025-06-18`. The [MCP setup guide](/docs/guides/mcp-setup/) wires the server into an agent.

| Tool | Read-only | Returns | CLI equivalent |
| --- | --- | --- | --- |
| `list_workflows` | yes | The flows discovered under this project | [`smthrs ls`](/docs/reference/cli/ls/) |
| `run_workflow` | no | The launch receipt with the run id | [`smthrs up`](/docs/reference/cli/up/) |
| `list_runs` | yes | Run summaries, optionally filtered | [`smthrs ps`](/docs/reference/cli/ps/) |
| `get_run` | yes | One run's summary | [`smthrs status`](/docs/reference/cli/status/) |
| `watch_run` | yes | Events of one run after a sequence | [`smthrs logs --follow`](/docs/reference/cli/logs/) |
| `get_run_events` | yes | Every recorded event of one run | [`smthrs logs --json`](/docs/reference/cli/logs/) |
| `explain_run` | yes | The run's forensic digest and diagnosis card | [`smthrs status`](/docs/reference/cli/status/) |
| `list_pending_approvals` | yes | Parked runs with the payload that releases each | [`smthrs ps --status waiting-approval`](/docs/reference/cli/ps/) |
| `resolve_approval` | no | The decision receipt | [`smthrs approve`](/docs/reference/cli/approve/), [`smthrs deny`](/docs/reference/cli/deny/) |
| `get_node_detail` | yes | One node's recorded output | [`smthrs output`](/docs/reference/cli/output/) |
| `get_chat_transcript` | yes | The run's turn-by-turn transcript | [`smthrs logs`](/docs/reference/cli/logs/) |

## The envelope

Every tool answers the 0.x envelope `{ ok, data?, error? }`, serialized into the text content block and repeated as `structuredContent`, with `isError` set when `ok` is false.

- Success: `{ ok: true, data }`.
- Failure: `{ ok: false, error: { code, message } }`, with the message redacted before it leaves the server.
- Stable codes the server raises include `unsupported` for the ten unimplemented tools, `unknown_tool` for a name this session does not expose, `INVALID_INPUT` for arguments that fail the tool's schema, `RESOURCE_LIMIT` past a published bound, and the control-plane failures mapped from the typed control error (such as `RUN_NOT_FOUND`, `PLAN_DENIED`, and `ALREADY_RESOLVED`).

One request or response frame is at most 4 MiB. One history result is at most 10,000 events and 1 MiB encoded. Crossing either boundary answers `RESOURCE_LIMIT`.

## Tools

The eleven supported tools, in the order `supportedTools` declares them.

### list_workflows

Lists the flows discovered under this project.

Parameters: none.

Returns: `data` is an array of flow items, one per discovered flow. Reserved `system/*` flows are filtered out, matching `smthrs ls`.

CLI equivalent: [`smthrs ls`](/docs/reference/cli/ls/).

### run_workflow

Plans a flow, approves the plan with scope `run`, and launches it.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `flowId` | string | yes | The flow to run, as `smthrs ls` names it. |
| `input` | object | no | The flow's input. |

Returns: `data` is the launch receipt, carrying the run id. A reserved `system/*` flow id answers `{ ok: false, error: { code: "unsupported" } }`, matching `smthrs up`.

CLI equivalent: [`smthrs up`](/docs/reference/cli/up/), which plans, approves with scope `run`, and launches in one invocation.

### list_runs

Lists durable runs, optionally filtered by flow or status.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `flowId` | string | no | Only runs of this flow. |
| `status` | string | no | Only runs in this status: `accepted`, `running`, `parked`, `waiting-approval`, `cancelled`, `completed`, or `failed`. |

Returns: `data` is an array of run summaries, one per matching durable run.

CLI equivalent: [`smthrs ps`](/docs/reference/cli/ps/), whose `--flow` and `--status` flags name the same filters.

### get_run

Reads one run's summary.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `runId` | string | yes | The run to read. |

Returns: `data` is the run's summary. A run the control plane does not have answers `{ ok: false, error: { code: "RUN_NOT_FOUND" } }`.

CLI equivalent: [`smthrs status <run-id> --json`](/docs/reference/cli/status/), which prints the runs-listing document filtered to the named run.

### watch_run

Reads the events of one run after a sequence. Returns immediately; poll to follow.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `runId` | string | yes | The run to watch. |
| `afterSequence` | integer, zero or greater | no | Only events after this sequence. |

Returns: `data` is `{ runId, status, events, sequence }`: the events after `afterSequence`, the run's status when known, and the latest sequence to poll from.

CLI equivalent: [`smthrs logs --follow`](/docs/reference/cli/logs/).

### get_run_events

Reads every recorded event of one run.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `runId` | string | yes | The run to read. |

Returns: `data` is the run's events, oldest first, bounded at 10,000 events and 1 MiB encoded.

CLI equivalent: [`smthrs logs --json`](/docs/reference/cli/logs/), which prints the raw recorded events.

### explain_run

Explains what happened in one run: status, cause, turns, calls, refusals, and cost.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `runId` | string | yes | The run to read. |

Returns: `data` is `{ runId, status, digest, card }`: the forensic digest of the run's events and the rendered diagnosis card.

CLI equivalent: [`smthrs status <run-id>`](/docs/reference/cli/status/), which prints the same diagnosis card.

### list_pending_approvals

Lists runs parked on an approval, with the payload that releases each one.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `runId` | string | no | Only this run. |

Returns: `data` is one entry per run parked at `waiting-approval`: `{ runId, flowId, question, approval }`, where `approval` is the serialized payload `resolve_approval` takes.

CLI equivalent: [`smthrs ps --status waiting-approval`](/docs/reference/cli/ps/) lists the parked runs; the payload itself is the `payload` field of the run's `control.approval.requested` event, readable with [`smthrs logs`](/docs/reference/cli/logs/).

### resolve_approval

Approves or denies a parked run with its serialized approval payload.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `approval` | string or payload object | yes | The serialized approval payload from `list_pending_approvals`. |
| `decision` | `"approve"` or `"deny"` | yes | What to do. |
| `scope` | `"once"`, `"run"`, or `"remembered"` | no | How long the grant lasts. Omitted means `once`. |

Returns: `data` is the decision receipt. A payload that does not decode, a `decision` outside the two values, or a `scope` outside the three answers `INVALID_INPUT`. The `once` default is deliberate: `smthrs approve` defaults its `--scope` to `run` interactively, while an argument an MCP client never sent must not widen what it may do.

CLI equivalent: [`smthrs approve`](/docs/reference/cli/approve/) and [`smthrs deny`](/docs/reference/cli/deny/).

### get_node_detail

Reads one node's recorded output from a run.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `runId` | string | yes | The run to read. |
| `nodeId` | string | yes | The node, as `smthrs output <run-id>` lists it. |

Returns: `data` is the node's recorded output. A node the run did not record answers `{ ok: false, error: { code: "NODE_NOT_FOUND" } }`, with the ids the run has in the message.

CLI equivalent: [`smthrs output`](/docs/reference/cli/output/).

### get_chat_transcript

Reads one run's turn-by-turn transcript.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `runId` | string | yes | The run to read. |

Returns: `data` is `{ runId, transcript }`, the transcript rendered from the run's recorded events.

CLI equivalent: [`smthrs logs`](/docs/reference/cli/logs/), whose human output is the same transcript projection.

## Surfaces

The `--surface` flag chooses which tool families a session exposes; `--read-only` and `--allowed-tools` then filter the choice.

- `semantic` (the default): the eleven supported tools plus the ten named-but-unsupported tools below.
- `--surface raw`: one `cli_<verb>` directory tool per shipped CLI verb, dashes rewritten as underscores. A raw tool executes nothing: it answers `{ ok: true, data: { command, description, note } }`, a pointer to run `smthrs <verb>` from a shell while the semantic tools perform the control-plane operations directly.
- `--surface both`: the union of the two.
- `--read-only`: drops every tool whose read-only hint is false (`run_workflow` and `resolve_approval`).
- `--allowed-tools name1,name2`: keeps only the named tools.

## Named but unsupported

The ten 0.x tool names 1.0.0-rc.0 does not implement keep their names and answer `{ ok: false, error: { code: "unsupported" } }`, so an agent's call fails with a reason instead of as an unknown tool. The message points at `https://smithers.sh/migration/1.0`.

| Tool | Why it is unsupported |
| --- | --- |
| `revert_attempt` | Time travel is a library API (`@smthrs/time-travel`) and is not composed into the CLI. |
| `fork_run` | Time travel is a library API (`@smthrs/time-travel`) and is not composed into the CLI. |
| `replay_run` | Time travel is a library API (`@smthrs/time-travel`) and is not composed into the CLI. |
| `rewind_run` | Time travel is a library API (`@smthrs/time-travel`) and is not composed into the CLI. |
| `restore_checkpoint` | Worktree lanes and snapshot restore are deferred. |
| `list_snapshots` | Worktree lanes and snapshot restore are deferred. |
| `get_timeline` | Time travel is a library API (`@smthrs/time-travel`) and is not composed into the CLI. |
| `time_travel` | Time travel is a library API (`@smthrs/time-travel`) and is not composed into the CLI. |
| `list_artifacts` | The artifact projection is not part of this release. |
| `ask_human` | There is no question or answer RPC; approvals park the run, so use `list_pending_approvals`. |
