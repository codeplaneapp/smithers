Smithers 0.28.0 makes long-running agent work easier to operate, distribute,
and trust. The Monitor is now a full operations console. Workflow packs can be
installed, updated, ejected for local editing, and shared. Provenance bindings
stop a task when the approval or artifact that authorized it has changed.
Delegation gains both a fixed `DelegationChain` and the experimental, adaptive
`Trellis`. Durable memory notes turn observations into reviewable knowledge,
and a new runtime adapter runs the real workflow driver in Node or a browser.

This release also contains a broad reliability and security pass across the
engine, Gateway, CLI, time travel, database backends, integrations, agents,
sandbox providers, and the shipped workflow pack.

---

## Monitor: a full operations console

The Monitor is now where you understand and steer a run, rather than a page you
open only to check whether it finished.

- **Always-on run health** diagnoses stalled, stale, orphaned, quota-parked,
  and terminal runs. A one-click Resume action handles recoverable runs.
- **In-browser session hijack** opens a node's real agent session through a PTY
  websocket channel, with per-node hijack candidates supplied by the Gateway.
- **Live agent transcripts and structured output** open at the newest events
  and keep streaming while a busy run produces more output.
- **DevTools inspection** includes an interactive XML tree, frame scrubber,
  activity feed, diff view, timeline, scores, crons, operations statistics,
  quota state, and run or task controls.
- **Large-run navigation** adds container rollups, failure reasons, notable
  event filtering, and a paginated all-runs table.
- **Agent attribution** follows every task through declared agent, acting
  engine, model, failover position, and attempt history.
- **Embedded guest mode** uses `?embed=1` for chrome-less run detail or
  rail-less overview pages, fail-closed host-origin messaging, and explicit
  `?theme=` parity. The iframe-safe cancel flow no longer depends on
  `window.confirm`.
- **Accessibility and responsiveness** now have keyboard, focus, reduced
  motion, light/dark theme, authenticated recovery, and narrow-layout browser
  coverage.

The CLI opens the Monitor when a run starts. `bunx smithers-orchestrator
monitor` remains the direct entry point for an existing run or workspace.

## Workflow packs: install, update, edit, share, and remove

Workflow packs are a complete lifecycle in 0.28.0.

```bash
bunx smithers-orchestrator add user/repository --yes
bunx smithers-orchestrator packs list
bunx smithers-orchestrator packs update
bunx smithers-orchestrator eject pack-name:workflow-name
bunx smithers-orchestrator share --dry-run
bunx smithers-orchestrator remove pack-name
```

- **`smithers.toon` manifests** declare a pack's name, description,
  repository, workflows, and UIs. `init` scaffolds the manifest, including an
  agents-only initialization.
- **Local and global discovery** finds installed packs, validates their
  manifests and import closure, scans JavaScript pack modules, and reports
  whether a workflow is eligible to run.
- **Qualified names remove ambiguity.** A pack workflow can be addressed as
  `pack-name:workflow-name`; an unqualified local workflow shadows the pack
  copy.
- **Updates are explicit.** `packs update NAME` refreshes one locked pack, and
  bare `packs update` refreshes all of them without touching local files.
- **Removal is explicit and scoped.** `remove NAME` uninstalls a local pack;
  `remove NAME --global` removes its global installation. Ejected local files
  are separate and remain yours.
- **`eject` makes a workflow yours.** It copies the workflow plus its relative
  UI, prompt, library, stylesheet, Sass closure, directory imports, aliases,
  re-exports, and asset leaves into the local `.smithers` tree. Collision and
  rollback checks prevent a partial local copy.
- **Sharing is durable.** The seeded `share-pack` workflow validates and, when
  necessary, completes the manifest before preparing a repository and registry
  pull request. The `add` and `share-pack` system workflows make both sides of
  the lifecycle runnable and inspectable.
- **Pack writes are non-destructive.** Installs use a staged, symlink-safe,
  same-filesystem swap. Publishing works from a staged copy, never the live
  pack, strips local agent configuration, supports idempotent retries, and
  cleans its temporary state on every terminal path.

See [Workflow packs](/reference/packs), [`add`](/workflows/add), and
[`share-pack`](/workflows/share-pack).

## Provenance-bound execution

Approving an artifact should authorize that artifact, not whatever happens to
occupy the same output slot later. Provenance binding makes that rule part of
the engine.

```tsx
const approval = ctx.prove("review", { nodeId: "lane:review" });

<Task id="lane:publish" bind={approval} agent={publisher}>
  Publish the reviewed artifact.
</Task>
```

`ctx.prove()` captures a digest of the exact upstream row. `<Task bind>` checks
that digest again at schedule time. If the row changed, the task parks as
`BOUND_STALE` instead of acting on stale authority. The state is visible to
workflow code through `ctx.boundStale("lane:publish")` and to operators through
`bunx smithers-orchestrator why`, so a correction loop can produce and approve
a new artifact without failing the run.

Bindings are carried through graph extraction, scheduler state, persisted task
metadata, DOM compatibility paths, and generated types. SHA-256 behavior is
verified against standard vectors and the active platform crypto provider.

See [Provenance binding](/concepts/provenance).

## Fixed and adaptive delegation

Smithers now ships two delegation models.

- **`DelegationChain`** is the fixed, inspectable composite for goal
  refinement, planning, preview, execution, review, scoring, and bounded
  re-planning. Its workflow and multi-file UI ship in the pack, and
  `gateway-react` exposes the durable delegation event fold.
- **`Trellis`** is the experimental adaptive model. Sol or Fable authors a
  bounded `agent | sequence | parallel` intermediate representation from
  settled evidence; Smithers validates and compiles it into ordinary tasks in
  the same run. Terra and Luna can complete bounded work but cannot author more
  graph structure.

The fixed chain includes probe-judgment, plan-solidity, estimate-accuracy,
tier-fit, and human-poll scorers with weighted run aggregation. Shared token
prices and `estimateCostUsd` keep cost forecasts consistent across the chain,
review app, and workflow helpers.

Trellis has deterministic program digests, immutable recursive fuel,
depth/fan-out/prompt limits, one bounded semantic-repair turn, strict output
contracts, canonical settlement, and explicit handling for runtime failure and
fuel exhaustion. Direct Sol/Fable implementation is disabled unless the caller
supplies a critical-execution policy with category, path, line, and independent
review constraints. Its custom UI shows accepted and rejected generations,
fuel allocation, real node outputs, events, and the final canonical outcome.

Trellis is not part of the default init pack in this release. It is available
as a repository workflow and public component for experimental use. See
[`<Trellis>`](/components/trellis) and the [`trellis`](/workflows/trellis)
workflow.

Agent tasks also gain `maxSchemaRetries`, so workflow authors can budget or
disable hidden structured-output correction calls. Exhausted delegation leaves
now fail instead of being mistaken for completed work.

## Durable knowledge across runs

The memory package gains an append-only notes layer for knowledge that should
survive one run without becoming mutable ambient state.

- Facts, messages, and notes can carry explicit run, node, and iteration
  provenance.
- Notes are append-only and idempotent. A supersession junction records which
  accepted note replaced which older observations without deleting history.
- `pending`, `accepted`, and `rejected` status is the one mutable field. The
  default read contract returns accepted notes that have not been superseded by
  another accepted note.
- Full-text search is opt-in and created lazily per namespace kind, so unused
  namespaces pay no FTS write cost.
- `saveNote`, `getNote`, `listNotes`, `setNoteStatus`, `enableNoteSearch`, and
  `searchNotes` are published through both the store and Effect service APIs.
- The `incident-runbook-memory` example shows ordinary tasks banking
  provenance-stamped lessons, proposing a consolidated rule, waiting for human
  approval, and serving that accepted rule to the next incident.

The notes and FTS implementation is SQLite-only in 0.28.0 and fails with an
explicit backend error on Postgres or PGlite. Facts and messages keep their
existing backend support.

## Workflows declare their own views

- **`<UI>` and `<TUI>` components** let a workflow declare its browser and
  terminal views inline. The Gateway resolves them through the run's
  `entryFile`, while `ui/<key>.tsx` convention entries are discovered at
  request time.
- **`@smithers-orchestrator/ui`** is a token-native component library with
  shadcn anatomy, shared by seeded workflow UIs and init templates. Gateway UI
  bundles use production React and stamp the theme before first paint.
- **`create-ui`** has one agent author and verify a custom UI for an existing
  workflow. It is shipped as a curated system workflow, so the Monitor's
  Create UI action works outside the Smithers development repository.
- A UI architecture gate tracks package boundaries, shared primitive usage,
  and shadcn provenance.

## Runtime portability and child workflows

The workflow driver now runs behind a typed `RuntimeAdapter` for clock,
storage, identifiers, task execution, files, subprocesses, worktrees, and
sandboxes.

- **`smithers-orchestrator/browser`** runs the real `WorkflowDriver`, renderer,
  graph extraction, and core workflow components in a browser. Unsupported
  filesystem, subprocess, sandbox, or worktree operations fail with
  `RUNTIME_CAPABILITY_UNAVAILABLE`.
- **Node-compatible entry points** keep the same workflow core loadable without
  pulling a static Bun SQLite dependency through the module graph.
- **Five-runtime conformance coverage** exercises Node, Bun, browser,
  Cloudflare Workers, and Vercel, including a real headless browser
  and a packed npm consumer.
- **`WorkflowFileRef`** lets `<Subflow>` run a workflow module generated at
  runtime, with its file lifecycle linked to the child node.
- **Child-run lineage** can be supplied from the CLI with `--parent-run-id` and
  is persisted for inspection, cancellation, and MCP consumers.
- **Prefer-resume fan-out** reuses a matching child run after a parent resume,
  and runnable `childRun` references can expose workflows with several output
  tables instead of only a conventional final table.

## Engine, scheduler, and time travel

- **Owned worktree lifecycle:** `bunx smithers-orchestrator worktree list` shows
  the run that owns each worktree, and `bunx smithers-orchestrator worktree
  prune` safely reclaims completed-run worktrees. Dirty worktrees and branches
  with unpushed commits are always preserved.
- **Demand-driven concurrency:** the scheduler derives a useful default from
  declared parallel widths, raises `maxConcurrency` when runnable work would
  otherwise starve, honors `subtreeConcurrency`, and emits one warning when a
  pinned cap remains saturated.
- **Numeric `priority`** orders tasks competing for a concurrency-limited slot.
- **`failurePolicy="quarantine"`** lets a container isolate a failed child
  without failing the whole run.
- **Graceful pause:** `bunx smithers-orchestrator pause` and the `pauseRun` RPC
  stop scheduling new work, allow in-flight tasks to finish, and park the run
  in a resumable `paused` state.
- **Single-owner terminal cancellation** uses a compare-and-set claim. Pending
  approvals, human requests, events, and timers finalize durably, and surviving
  owner processes are reaped by `cancel` and `down`.
- **Quota parking** fails over to another agent before parking, keeps task and
  workflow identity stable through resets, auto-wakes at the known reset time,
  and can now be cancelled through the control plane.
- **Replay-sensitive tools require approval.** The MCP contract marks replay
  destructive, prompts before destructive time travel, and parks replay-unsafe
  tool use behind an approval gate.
- **Content-addressed snapshot payloads** deduplicate identical large states.
  Rewinds are serialized behind durable leases, replay re-blesses the edited
  workflow hash, and truncation is correct even when every retained frame is
  newer than the target attempt.
- **Schema defaults apply before validation.** Zod defaults in the workflow
  input schema are now present in `ctx.input` on a new run.
- **Structured-output correction is bounded** by `Task.maxSchemaRetries` and
  retains the task root, output limit, task context, and retry policy.
- Concurrent `WatchTree` waiters are supported, durable deferred resolutions
  are bounded, malformed waiting timers keep an attempt-relative anchor, and
  compute-task timers are cleared after completion.

## Gateway, protocol, and control plane

- **A protocol-owned Gateway RPC module** is now the wire-contract source of
  truth. Gateway, gateway-client, gateway-react, and their generated
  declarations consume the same method and row types through focused subpaths.
- **Cross-run score comparison** adds `listScoresForRuns`, `getScoreDetail`,
  and `GET /v1/api/scores/compare`.
- **Saved eval suites** store cases and launch the hidden `eval-suite-run`
  system workflow. Each case runs as a real child workflow and is graded
  against an expected value or assertion specification.
- **Run recovery over the wire** adds `retryTask`, node-state reads, graceful
  pause, and the `whatHappened` summary route.
- **Final run diffs over RPC** add `getRunDiff` plus gateway-client and React
  bindings and a closed, generated response type. Terminal revisions are
  resolved per checkout lane and merged, with durable node-diff cache fallback
  after a checkout is reaped. The response preserves an honest empty patch
  list and returns an explicit oversized marker instead of silently truncating
  the result.
- **Accessible control requests** use a real dialog with keyboard and focus
  behavior rather than an inaccessible browser prompt.
- **Control-plane mutations and audit records** commit atomically, project
  usage limits cascade to their children, and quota-parked runs accept
  cancellation.
- **Run-event replay order and cron ownership** are stable under reconnects and
  concurrent ticks. Multiplayer run forests preserve parentage while parked
  streams recover.

## CLI

- **`bunx smithers-orchestrator status RUN_ID`** gives a compact health verdict,
  node counts, agent/model mix, throughput, and current blockers.
- **`bunx smithers-orchestrator what RUN_ID [NODE_ID]`** uses a cheap agent to
  narrate the recorded facts, with a deterministic fallback when no agent is
  available.
- **`bunx smithers-orchestrator review`** runs code review plus a story-form
  HTML walkthrough for a repository or pull request.
- **`bunx smithers-orchestrator upgrade`** reads the relevant changelogs,
  upgrades with a cheap agent, and escalates only when necessary. Workflow
  packs update separately through `packs update`.
- **Scoped supervision** watches and resumes stale runs only when their recorded
  owner process is verifiably dead.
- **Init redesign** asks one agent-selection question, then opens a hijacked
  tutorial session. The init pack is focused on authoring workflows, with older
  starters kept under `examples/`.
- **`up --dry-run`** redirects to `bunx smithers-orchestrator graph`, the
  non-executing construct check.
- **SOTA registry** publishes a canonical model table, benchmark results, a
  daily research cron, a drift check, and a notice when a newer registry ships.
- Global-pack root overrides, JavaScript pack modules, duplicate home workflow
  directories, invalid subcommands, semantic MCP timeouts, and token-store
  writes now have explicit, bounded behavior.

## Security hardening

- **Credentials stay on their origin.** Generic HTTP and OpenAPI tools, Exa
  and API-key search providers, ElevenLabs TTS, the Anthropic review proxy,
  and integrations drop sensitive headers before a cross-origin redirect.
- **Network destinations are validated.** Agent HTTP tools reject malformed or
  non-HTTP base URLs, GitHub integrations reject foreign API URLs, and provider
  stream-log paths stay inside their realpath-confined root.
- **Pack and token writes are atomic.** Pack installs and shares use staged,
  symlink-safe copies; the CLI token store is written through a secure atomic
  replacement.
- **Approval restrictions fail closed.** Malformed access restrictions are
  rejected, custom scopes match literally, destructive MCP time travel asks
  for confirmation, and legacy RPC aliases cannot resolve prototype keys.
- **Local UI proxies require a loopback Host.** Embedded cross-origin messages
  also require the explicit host origin.
- **Gateway websocket admission** has an authentication deadline, isolated
  unauthenticated capacity, subscription caps, and one heartbeat scheduler per
  socket.
- **Structured secrets are recursively redacted** from observability data, and
  Telegram removes bot tokens from network errors.
- **OpenAPI protected headers are case-insensitive**, and Electric proxy shape
  templates cannot be weakened by a caller-supplied `where` clause.
- **Abort signals and response-size bounds** propagate through tools,
  integrations, parsing, transcription, and provider calls.

## Performance

- Per-node event reads use one SQL pass, gateway-client invalidations coalesce
  instead of causing refetch storms, and Monitor node inspection keeps loading
  states honest while avoiding redundant reads.
- Engine frame snapshots are incremental. Worktree fetches use a bounded TTL
  cache, and patch-identical rebases skip needless work.
- Gateway boot loads workflow modules concurrently, production UI bundles serve
  production React, and the ticket-fleet pipeline can run wide sweeps with
  separately bounded implementation lanes.

## Behavior and upgrade notes

- Completed-run worktrees are reaped by default. Set
  `RunOptions.keepWorktrees` or `SMITHERS_KEEP_WORKTREES=1` to opt out. Dirty or
  unpushed worktrees are always preserved.
- `supervise` requires an explicit scope. It resumes only a run whose recorded
  owner PID is verifiably dead.
- Zod defaults in the input schema now apply before validation and are visible
  through `ctx.input` on a new run.
- Unsupported nested-loop lanes fail during graph extraction with both loop IDs
  in the `NESTED_LOOP` error. Supported per-item correction loops behind a
  `Parallel` or `Worktree` fork keep working.
- `replay_run` is marked destructive in agent contracts, and replay-unsafe tool
  use requires approval.
- Installed pack workflows are read-only. Use `eject` to create an editable
  local copy that shadows the installed workflow.
- Memory notes and note search require SQLite in this release.
- Trellis is experimental, is not in the default init pack, and requires the
  workflow's `maxConcurrency` input to match the pinned run cap.
- `PoolAgent` is exported but is not installed into the default agent config.
- Browser workflows receive typed capability errors for Node-only operations.
- `up --dry-run` prints the graph instead of partially starting a run.
- Fresh init packs are intentionally smaller. Archived starter workflows remain
  available under `examples/`.
