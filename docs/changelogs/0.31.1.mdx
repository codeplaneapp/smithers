**Smithers 0.31.1 is here!** This is a hardening release, and we are saying
so up front: 163 commits since 0.31.0, and 80 of them are fixes. The theme is
truthfulness. Reviews that could not run no longer read as rejections, eval
failures caused by the harness no longer read as workflow regressions, and
the testing harness no longer masks real bugs as passing tests. Alongside
that, run recovery gets friendlier, runs can now watch and heal each other,
and sandboxed tasks can finally reach your local dev server.

## Upgrading

```bash
bunx smithers-orchestrator update        # upgrade the CLI
bunx smithers-orchestrator upgrade       # agent-assisted: reads the changelogs and applies what your project needs
bunx smithers-orchestrator packs update  # refresh installed workflow packs
```

Behavior changes are collected in the [upgrade notes](#upgrade-notes) at the
bottom.

## create-workflow stops overbuilding

<!-- MEDIA GAP: create-workflow tier routing needs a recording -->

Asking the builder for something simple used to get you a full workflow
anyway. The clarify stage now classifies every request into one of three
tiers before building anything: a direct edit, a `smithers oneshot`, or a
real workflow. Simple asks end at status `routed-simple` with the exact
command to run instead of scaffolded files you did not need.

```bash
bunx smithers-orchestrator make-workflow "fix the failing lint rule in packages/engine"
# => routed-simple: run `smithers oneshot "fix the failing lint rule in packages/engine"`
```

- Large single-goal asks route to oneshot too: one strong agent handles
  goals up to roughly 300k tokens in a single run, so "it feels big" no
  longer earns a multi-node workflow.
- Oneshot itself gained a preflight that warns on a dirty working copy and
  has the agent triage it before starting the goal, plus a steerable
  monitor UI reusing the workspace `smithers monitor <runId>` entrypoint.

## Blocked is not rejected, inconclusive is not failed

<!-- MEDIA GAP: blocked review verdict / INCONCLUSIVE eval run needs a recording -->

Two failure-attribution fixes that change what your repair loops do next:

- **Review verdicts carry a required `blocked` field.** When a reviewer
  could not run its verification for an environmental reason (network down,
  missing credential), it sets `blocked: true` and names the cause instead
  of rejecting work it never actually reviewed.
- **Eval runs grade harness deaths as INCONCLUSIVE.** When a case dies with
  a harness signature rather than a workflow defect, it is stamped
  `inconclusive: true`, and `bunx smithers-orchestrator eval` exits code 5 (instead of 1)
  when every red case is inconclusive. A repair loop seeing exit 5 knows to
  fix the harness, not the workflow.

```bash
bunx smithers-orchestrator eval my-workflow --suite evals/cases.jsonl
# exit 0: green   exit 1: real regressions   exit 5: all reds were harness failures
```

A new `eval-driven-development` skill documents the surrounding discipline:
classify red before acting, ratchet on green, and circuit-break to a human
when the loop stops converging.

## Recover a run without losing your workflow edit

<!-- MEDIA GAP: retry-task --accept-workflow-change needs a recording -->

Editing a workflow while one of its runs sat failed used to dead-end
recovery: `retry-task` died on `RESUME_METADATA_MISMATCH`, and your only
outs were forking from a checkpoint or starting fresh. The flag that `up`
already had now works on recovery too:

```bash
bunx smithers-orchestrator retry-task RUN_ID NODE_ID --accept-workflow-change
```

- The `RESUME_METADATA_MISMATCH` error now names
  `--accept-workflow-change` directly, so you learn the fix from the error
  instead of the docs.

## Runs that watch and heal other runs

<!-- MEDIA GAP: monitor workflow auto-heal needs a recording -->

Long-running work fails in boring ways: a run stalls, a node wedges, and
nobody notices for an hour. Runs launched through `smithers monitor` now get
a first-class monitor workflow at `.smithers/monitor/<workflowId>.tsx` that
watches one sibling run, auto-heals `stalled` and `wedged-node` conditions,
and escalates everything else through a durable HumanTask instead of
guessing.

`smithers claude monitor` also breaks silence on two new signals:

- **Retry churn:** `node-retrying` fires when an active attempt reaches the
  alert threshold (default: the 3rd retry).
- **Quiet runs:** `run-progress` fires when a followed non-terminal run has
  written no output for the threshold window (default: 30 minutes).

Both thresholds are configurable via `--retry-alert-attempt` and
`--progress-every-ms`.

## Sandboxed tasks can reach localhost

`allowNetwork: false` used to mean no network at all, which broke the most
common local loop: an agent testing against its own dev server or a local
Postgres. It now means no egress: loopback traffic stays reachable while
remote destinations stay denied, and the denial error names the
`allowNetwork` escape hatch instead of failing mutely.

```tsx
<Task id="verify" sandbox={{ allowNetwork: false }} output={outputs.check}>
  Start the dev server and verify http://127.0.0.1:3000/health returns 200.
</Task>
```

## A testing harness that tells the truth

80 fix commits and 8 test commits landed this release, and the most
important ones fixed the tools that vouch for everything else. Three
`coverWorkflow` defects were masking real bugs as passing tests:

- **Loop caps clamp instead of overwrite.** A declared
  `<Loop maxIterations>` lower than the harness cap was silently raised;
  it is now `Math.min(declared, cap)`, so your workflow's own bound wins.
- **`unusedMocks` is satisfiable again.** The harness's own injected `"*"`
  catch-all mock no longer appears in the caller's dead-mock list.
- **Compute simulations exercise real arithmetic.** The stacked-ship
  simulations ran with compute tasks stubbed, so summary assertions were
  reading schema-example placeholders; with `executeCompute: true` they
  caught a real ordering bug where the terminal summary fired before
  reviews settled and reported 0 approved. All three simulations are
  re-enabled: 22 pass, 0 fail.

Two engine fixes in the same spirit, where "done" was being claimed before
work was done or bytes were restored:

- **Async `<Task deps>` children are awaited exactly once.** An async deps
  callback could previously be treated as a static payload, letting the
  engine claim completion while real work, including child runs, was still
  pending.
- **jj attempt pointers record `commit_id`, not `change_id`.** Because jj
  keeps `@` on one change across attempts, revert and timetravel could
  resolve to the change's current commit: the DB rewound while the
  filesystem silently did not. Pointers now pin the exact working-copy
  snapshot, so restores move real bytes.

## Other improvements

- New `packages/ui-core` and `packages/tui-ui` packages extract the runs
  domain (list, tree, event frames, diff, health, ETA) shared by the web UI
  and TUI into one implementation, phase 1 of the TUI parity program.
- New workflow packs: `api-ab-benchmark`, `smithers-repo-federation`,
  `stacked-ship`, `whole-foods-meal-planner`, `sol-issue-train`,
  `xcombo-fix-train`, and `tui-parity`.
- OrchBench results are committed at `benchmarks/orchbench/RESULTS.md`: a
  solo frontier agent scored 0.901 against a three-model review panel's
  0.734, with the panel costing 2.1x the wall clock.
- Parent/child subflow hardening across approvals, cancel and pause, retry,
  snapshots, and rewind leases landed as roughly 30 numbered engine fixes.
- The pack installer resolves `bun` from PATH explicitly, fixing a bun
  1.3.x case where spawning the bare name silently reused the running
  binary.
- The gateway-ui `ApprovalPanel` and the create-workflow UI picked up
  accessibility, loading-skeleton, and decision-feedback polish.

## Upgrade notes

- `reviewOutputSchema` and `reviewSynthesisSchema` verdicts now require a
  `blocked` field. Parsing defaults it to `false`, but fixtures or
  consumers that construct verdict objects by hand must add it.
- `coverWorkflow` now clamps a declared `<Loop maxIterations>` to the
  configured cap instead of raising it. Loops that relied on the old
  behavior run fewer iterations, matching their declared bound.
- CI scripts wrapping `bunx smithers-orchestrator eval` should treat exit code 5 (every red
  case inconclusive) as a harness signal, not a workflow regression.
