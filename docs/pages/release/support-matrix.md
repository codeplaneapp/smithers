# rc.0 support matrix

This page states what Smithers 1.0.0-rc.0 supports. Everything it does not
support is in [known limitations](/release/known-limitations).

The tables below are generated from
[the release contract](https://github.com/smithersai/smithers/blob/main/docs/migration/rc-contract.md),
which is frozen for this candidate. A row here and a row there are the same row.

## Run control

| Feature | Contract |
| --- | --- |
| Cancel | `smithers cancel`, `Control.cancel`, and the `Cancel` RPC record `RunStore.requestCancel` on the engine row durably regardless of which process owns the run, then interrupt a local fiber if present. The engine cascade (`descendantsOf`, `requestCancelDescendants`, `inheritParentCancellation`, `retainedScopes`) delivers it within one heartbeat tick in the owning process. A cancel against a terminal run returns the `Terminal` receipt and writes no event. |
| Signals | `smithers signal RUN_ID {name, payload}` persists the `control_run_messages` row, journals `control.signal.delivered`, and completes the matching `WaitFor` deferred (`DurableEngineState.completeDeferred`) keyed by signal name; a run parked on `WaitFor` wakes within one heartbeat tick. |
| Approvals | Plan-level approval for `deployClass` flows and node-level approval (`ask`) park the run as `waiting-approval`; `approve`/`deny` take the serialized `ApprovalPayload`, scope `once\|run\|remembered`, principal stamped by the server; `control.approval.requested` carries the exact approve argument. `Approve` on a `Node` target resumes the run server-side so a gateway client does not need a second call. |
| Steer | `Control.steer` and the `steer` verb; provenance `sourceActor = <principal.kind>:<principal.id>`. |
| Retry bounds | An action's `RetryPolicy` `maxAttempts` and `expirationMs` survive park, resume, and process death: the durable driver persists the attempt sequence and the first attempt's start time, and the engine resumes the counter and the wall-clock origin from them (`packages/engine/src/FlowEngine/make.ts:354-392`, `actionRetryOrigin` and `actionLatestAttempt`). The suspended-flow polling budget (`suspendedRetryPolicy`) is per caller by design (`make.ts:194-201`). A pruned attempt row restarts the `expirationMs` budget from the current clock with a logged warning (`make.ts:366-378`); that is a documented limit. |
| Resume and ownership | `run --resume` is join-or-claim; a live peer's run returns `ClaimLost`. Heartbeat 1 s, stale after 30 s with 10 s skew; steal requires `LivenessEvidence`; `RunDriver` sweeps stale-running rows (64 per tick) and released rows every tick. The default `isAlive` is the same-host pid probe from `@smthrs/run-store` `Ownership.LivenessProbe`; the CLI no longer hard-codes `() => Effect.succeed(false)`. One engine process per project directory remains the documented posture. |
| Time travel | Library API only: `TimeTravel.inspect`, `replay`, `fork` (refuses when an ancestor is live; provisions the jj workspace before committing), `rewind` (compensation, jj restore, archive, suspend). |
| Retention | `smithers gc` (section 4.1). Journal compaction stays opt-in. |
| Sync bounds | Workspace subscriptions use a configurable concurrency bound and bounded `PubSub`s; `SyncClient` uses a real credit window. Server stays loopback-only by default. |
| Process containment | Cooperative cancellation of a run kills the process group of every child the kernel spawner started, including a child that ignores `SIGTERM`; no `PPID 1` orphan survives a cancel. A hard-killed engine process is not covered (section 5.2, X-17). |

## What runs where

Support means durable engine execution. A package that bundles for a platform is not necessarily runnable there. The supported production target is Node.js `>=22.19.0` with local SQLite.

| Platform or storage | Status | What is supported today |
| --- | --- | --- |
| Node.js `>=22.19.0` with local SQLite | Production | The supported production target. `NodeDatabase` uses `@effect/sql-sqlite-node`; the root and database package manifests require Node.js `>=22.19.0`. |
| Bun, non-durable packages | Experimental | CI runs the artifacts, canonical, capability, crypto, engine, flow, keys, platform-browser, platform-bun, and sandbox suites. |
| Bun durable engine | Unsupported | The Bun CI lane excludes database, engine-store, journal, kernel, plan, run-store, step-cache, sync, time-travel, and example suites. It does not establish durable-engine support. |
| Browser bundles | Experimental | CI proves that browser-safe entry points bundle and that documented Node-only entry points remain Node-only. No browser execution suite exists, and this repository ships no browser SQL client layer. Browser durable execution is not supported for production. |
| PostgreSQL or PGlite | Unsupported | `DurableWriter` accepts a generic `SqlClient` and classifies transient PostgreSQL/PGlite failures, but no PostgreSQL or PGlite client layer or migration ladder ships. |
| Cloudflare or Vercel edge deployments | Experimental | Adapters live in the separate plugins repository and remain incomplete. Edge deployments are not supported for production. |

## Implemented

| Area | Current behavior |
| --- | --- |
| Flow definitions | Typed `Flow.make`, registration layers, explicit or idempotency-derived execution IDs |
| Recorded steps | Typed `Action.make` with success/error schemas, tiers, metadata, annotations, and encoded exits |
| Action implementation resolution | Two halves, one for each side of the type system. **Compile time:** `Action.make` mints a requirement keyed by the action tag, `Charge.call(payload)` records a node carrying it, `Flow.make` reads the union off the node its body returns, and `Flow.execute` collects it, so a plan whose action has no `toLayer` layer does not compile, and a forgotten implementation is an error at the call site instead of a run that dies partway through. `.call()` propagates the channel because an inline callee's steps join the caller's plan; `.child()` and `.to()` drop it, because each is an execution boundary whose driver provides its own context, and dropping it at `.to()` is what keeps a self-looping lineage's type finite. `Sleep` and `WaitFor` are declared with `Action.makeSystem` and mint nothing: the engine owns those implementations, so an author cannot be the one who forgot them. **Run time:** the name-keyed `Implementations` table is unchanged and remains the resolution mechanism, because a driver expanding a plan read back out of a journal has no types left to consult, replay and resume address an action by the tag the persisted node carries. `toLayer` provides the requirement AND files into the table when a composition wired one up; the table stays optional, so a composition driving only behavior registered directly with the runtime still type-checks honestly |
| In-memory runtime | Flow execution, polling, suspension, resume, interruption, deferreds, clocks, and action memoization |
| Durable run state | SQL-backed run rows, exact claims, activation fences, heartbeats, stale-owner steal, terminal transitions, lineage (`parent_run_id`), and cancellation requests that are durably recorded, polled by the owning driver on the heartbeat cadence, guarded inside both the re-activation and terminal-transition CAS, and delivered to parked runs by a sweeper (issues #26–#28: shutdown interruption releases a run reclaimably instead of cancelling it, cancel of a suspended run is swept and observed, and terminally closed runs never surface as live waiting rows); the sweeper itself is sandboxed, a transient defect (e.g. `SQLITE_BUSY` escaping `waitingRuns()`) is logged and retried on the next tick instead of silently killing delivery for the process lifetime (issue #44); an owner whose heartbeat *writes* fail keeps working only for the 19-second `heartbeatWriteTolerance`, eleven one-second ticks shorter than the 30-second steal cutoff, so it is always interrupted before a peer may steal the run (issues #47, #61); the same periodic sweep also enumerates stale-running rows (`staleRunningRuns`) and re-drives them through the claim/steal path, so a hard-killed owner (SIGKILL, OOM) no longer strands its run or makes `requestCancel` against it write-only (issue #53); the sweep fetches only actionable rows, reason `released` plus a `cancelRequested` filter predicate, instead of scanning every parked run with a per-row `store.get` (issue #68); and a wake for a flow not registered in the sweeping process logs a once-per-run structured warning and leaves the row parked instead of no-oping silently (issue #62) |
| Attempt state | Fenced attempt admission, a configurable in-progress vocabulary and checkpoint cap, optional upsert admission, first terminal result, an unfenced patch surface, and opaque metadata |
| Journal | Bounded optimistic telemetry queue, batching, idempotent producer events, paging, replay-then-follow streams, projections, a multi-writer-safe lifecycle path through `emitDurable` that allocates and commits the canonical sequence inside the write transaction, and `transact`, which extends that transaction over a caller's state projection (see crash consistency below); a lost telemetry batch takes only its own entries out of the pending set, so a later `flush` still waits for entries queued behind it (issue #60) |
| Journal redaction | One rule set (`Redaction`) applied at the journal's single encode chokepoint, `payload`/`meta`, with a `redact` option and `SqlJournal.layer` opt-out (issues #46, #58). Scoped to observability: `RunStore` state, `AttemptStore` checkpoint/error/outcome/meta, and `CacheStore` result/meta are executable state and round-trip verbatim, because rewriting them resumes the flow with the wrong data and can make persisted state fail schema decode (issue #72). A secret that must not persist is a `Redacted` field in the caller's state schema |
| Content addressing | `@smthrs/crypto` provides SHA-256 and `@smthrs/keys` provides canonical flow keys. The engine owns cache policy: it combines caller identity with a complete cache environment and filesystem boundary. The composition root declares that environment only when `cacheEnvironment` supplies complete capabilities; otherwise keys include the execution ID and stay run-local. Invocation keys are also run-local. Action ordinals are allocated per declaration identity and folded into each invocation key so concurrent declarations cannot renumber one another across replay. |
| Cache rows | First-writer-wins content-addressed results with run/sequence provenance |
| Persisted plan | `@smthrs/plan` is the public planner/action-graph API `docs/specs/Specs/Object Model.md` describes: `KeyMaterial` declares a node, `StepKey` compiles material plus resolved dependency digests into an `@smthrs/keys` `Key` (the compiler deleted at `f5f3dda`, revived above `@smthrs/keys` and producing `Key` rather than a second `sk1_` format), `Plan.compile` orders topologically and keys every node with **no I/O**, `Plan.append` grows the graph by generation, `PlanDiff` is `smithers plan --diff` as a value, and `PlanStore` persists it append-only under migration block `4000`: enforced by SQL triggers, not by convention. Detected write-set overlaps annotate BOTH members of the pair with the resolved `serialize`/`lane`/`fail` verdict and its runtime half; an ordering edge is deliberately not key material, so a serialized node keeps its cache hit. There is no reverse-dependency index and no invalidating node visitor: `docs/specs/Concepts/Engine Hardening Round 1.md` rejects both, and content addressing subsumes them |
| Plan scheduling | `EngineStore.PlanScheduler` drives a persisted plan end to end. It dispatches ready nodes through the same `internal/ActionPersistence` seam every action uses, shared step cache, workspace sandbox, attempt rows, fenced journal, all unchanged, under a key that folds the plan-time node key together with the boundary the host just measured. Admission is `docs/specs/Concepts/Concurrency.md`'s middle limit only (`steps`, and `agents` as its subset), ordered by declared priority plus one point per round waited, so priority changes latency without permitting starvation. Source paths, read by the plan, written by nothing in it, are measured once before the first dispatch and pinned, honouring the torn-run rule; produced paths are measured after their producer settles. Each node settles as one of four outcomes (`built`, `clean`, `failed`, `skipped`), Skyframe's `EvaluationState` quadruple adapted to a store that never serves a failure from cache. `packages/engine-store/test/PlanSchedulerProduction.test.ts` drives it under the production filesystem-plus-sandbox composition and proves the Bazel-shaped promise: edit one input, and only the cone below it re-runs while the untouched branch is a cache hit |
| Runtime conflict strategies | The plan-time pair annotation carries a runtime half (`docs/specs/Concepts/Runtime Conflict Strategies.md`). **delay/rebase** holds the dependents; they are not ready while the node is pending, and re-executes against the newly recorded base: the re-measure re-keys, so it is a new attempt rather than a retry of the same identity, and it is bounded by `rebaseLimit`. **stop/merge** stops the losing action and routes both lanes through an explicit merge node appended to the SAME plan as an ordinary elaboration, with no rebase budget of its own per `Worktree Lanes`' restart-or-fail landing contract. An unabsorbed conflict goes to reconciliation |
| Reconciliation seam | `EngineStore.Reconciliation` is the first consumer `flows.engine.expected-set-deviation` has ever had: the emitters shipped with isolated execution and nothing read them. It is a DI seam, not a plugin hook, and `layerDefault` is a deterministic verdict function in the vault's order of preference: **reorder** when every undeclared path is one another plan node declares it writes, **factor out** when another node in the run deviated on exactly the same paths (content addressing collapses the two extracted steps to one key by itself), and **fail** otherwise, because a deviation nobody can explain is the case that is genuinely wrong. A model-backed reconciler is a different `Layer` and lives in the agent repository (`.smithers/tickets/agent-reconciliation-flow.md`); this repository has no model dependency |
| Artifact store | `@smthrs/artifacts` is the content-addressed store the cache references by digest, extracted out of `StepBoundary`: atomic temp+fsync+rename publication under a two-hex fanout, digest-verified reads with distinct `ArtifactMissing`/`ArtifactCorruption`/`ArtifactStoreError` tags, digest verification of an existing blob on every `put` (a mismatch is healed by the atomic rewrite; the workspace-shared directory makes a remembered proof unsafe), and a conservative crash-orphan sweep. `RemoteArtifacts` speaks Bazel's dumb-HTTP CAS protocol (`GET`/`PUT`/`HEAD /cas/{digest}`, `POST /cas/findMissing`) over Effect's `HttpClient` tag; `CombinedArtifacts` is local-first, remote-second with local write-back |
| Remote step cache | `StepCache.RemoteCacheStore` (`GET`/`PUT`/`DELETE /ac/{keyDigest}`) and `StepCache.CombinedCacheStore` (local-first with write-back into the local SQL row). `EngineStore.ArtifactSync` and `EngineStore.CacheSync` own the ordering that makes the pair safe: `findMissing` → upload the missing → confirm, then the local cache row, and only then the shared entry: Bazel's REAPI constraint that an action result is uploaded after every blob it references. Every step of that stays outside the `DurableWriter` transaction, so no host call is ever held across a write; `CombinedCacheStore`'s `publication: "deferred"` mode is what leaves the shared write to the seam that runs after the commit. Neither publication step can fail a run: the result is already durable on this host, so a refusal withholds the shared copy and journals an `unpublished` provenance record instead. On lookup, a locally-missing artifact is a distinct `MissingArtifact` refusal, so the dispatch fetches it, writes it back, and retries the replay exactly once before falling through to a real execution. With no shared tier configured, `ArtifactSync.makeLocal()` makes all of it a no-op. The remote tier was write-idle while nothing could be admitted to the shared cache under the production boundary; isolated action execution retired that (see the row below and `docs/specs/Concepts/Trust Granularity.md`), so a production composition that pairs `StepBoundary.layer` with `WorkspaceSandbox.layerFileSystem` publishes through it |
| Capability kernel | Monotone capability sets, rules, attended/unattended grants, journal-backed decisions, and guarded Host layers |
| Host bundles | Node, Bun, browser, and deterministic test adapters. Cloudflare and Vercel adapters live in the separate plugins repository |
| Durable primitives | SQL-backed deferred completions and absolute clock rows, restart re-arming and wake recovery, durable queue API, and attached child flow wake-up |
| Sync | Read-only catch-up and credit-bounded follow over schema-backed Effect RPC |
| Extension | Durable-core policy uses dependency injection at the owning seam: `Inconsistency`, `OwnerIdentity`, `StepBoundary`, `Jj` and the rest of the closed host list, plus constructor options such as `clockFireRetryPolicy` and `suspendedRetryPolicy` (the per-caller polling budget for a suspended flow, not a run-level retry bound). The `@smthrs/plugin` kernel is the narrower extension point for the assembled `@smthrs/agent` cell host: it dispatches the configuration lifecycle and the host-owned `cellRegistry`, `cellFlows`, and `cellModelRequest` waterfalls. It deliberately has no engine-wide run, step, retry, cache, wait, checkpoint, or journal lifecycle hooks; see [design decisions](/design-decisions#d11-core-extension-is-dependency-injection-cell-loop-extension-uses-the-plugin-kernel) |
| Cache-conflict receiver | `EngineStore.Inconsistency` (`layerStrict` / `layerTolerant` / `layerNoop`): `CacheStore.put` conflicts are journalled as `flows.engine.cache-conflict` instead of discarded. **The core default is strict**: journal, then fail the run with `CacheConflictDetected`, which is Skyframe's throwing `GraphInconsistencyReceiver`; provide `Inconsistency.layerTolerant` to opt out |
| Run cycle detection | Cycle rejection is atomic in storage: `DurableEngineState.recordRunParent` inserts the durable parent edge and walks the child→parent chain inside one write transaction, rolling back and failing with `RunParentCycleError` on a hit (no in-process gate, no cross-owner arbitration, no withdrawal protocol, issues #29/#40/#54/#55/#56); the driver records the edge **before** creating the run row, so a rejected request leaves no durable trace, and maps the error to the typed `FlowCycleDetected` (`code: "flow_cycle_detected"`, declared by `Engine.FlowEngine`, in the error channel, not a defect). The edge and the run row are created in one storage transaction, so a crash between them leaves no durable orphan edge (issue #80). Writer serialization is a documented `DurableWriter.write` contract requirement (Postgres must run write transactions `SERIALIZABLE`), pinned by a cross-connection race test (issue #74). The edge table is the single cycle-detection input; GC is enforced by an `AFTER DELETE` trigger on `flows_runs` rather than by call convention, with `removeRunParentsForRun` kept for edge-only cleanup (issues #66/#81) |
| Waiting taxonomy | `DurableEngineState.park` / `wake` / `waiting` / `waitingRuns` with `reason`/`wakeAt`/`token` columns; the run driver parks every real suspension, a `FlowRuntime.annotateWaiting` declaration (`approval`/`quota`/token, issue #31) when present, else `timer` with the earliest clock deadline, else `event`, and wakes on resume, so sweepers observe production suspensions; an annotation is consumed once its awaited deferred resolves, so a later suspension parks under its own reason and timer `wakeAt` instead of a stale replayed one (issue #42) |
| Retry policy | `@smthrs/flow`'s `RetryPolicy`: data-shaped policy, pure `nextDelay`, `decideEffect` decision point driven by the persisted attempt count, and an `expirationMs` schedule-to-close bound (issue #36) measured from the durably persisted first-attempt start via the driver's `actionRetryOrigin`, so the wall-clock budget survives park/resume and process death (issue #45). The retry verdict is durable too: a persisted `failed` attempt row replays by rethrowing the persisted domain failure (never `AttemptAdmissionRejected`) and the attempt counter resumes from the driver's `actionLatestAttempt`, so a `nonRetryable` failure matches on resume without an extra dispatch and the backoff ladder is not re-slept (issue #59, Temporal mutable-state parity). When attempt 1 itself was pruned, `actionRetryOrigin` degrades to the earliest surviving attempt row; only when no row survives does the engine restart the budget from the current clock, with a logged warning (issue #69) |
| Lifecycle journal channel | Engine-store lifecycle events (run decisions, attempt lifecycle, deferred completions, clock schedules, interruptions, cache provenance/conflicts, and the plan graph's `plan-recorded` / `subgraph-appended` / `node-scheduled` / `node-settled` / `node-invalidated` / `node-reconciled`) are written with `emitDurable`: undroppable, and blocking until committed; attempt lifecycle appends are owner-fenced and a zombie owner self-interrupts on `fence_lost` |
| Crash consistency (WAL/state atomicity) | **Every lifecycle entry commits in the same write transaction as the executable state transition it describes.** `Journal.transact` opens that transaction; `RunStore`, `AttemptStore`, `CacheStore`, and `DurableEngineState` write through the same `DurableWriter`, so their writes join it as savepoints and either both halves are durable or neither is, the local analogue of Temporal submitting mutable state and its event batches as one persistence request. The pairs closed are: attempt admission + `attemptStarted`, the pre-image patch + `snapshotIdentified`, `attempts.finish` + `hardViolation`/`expectedSetDeviation`/`attemptFinished`, the cache provenance append + `CacheStore.put`, the run-row CAS + its `transitioned`/`quarantined`/`interrupt-released`/`claimed-and-activated` decision, the cancel transition + waiting-row clear + `interrupted`, the deferred completion row + `deferredCompleted`, and the clock row + `clockScheduled`. Publication is deferred with it: an entry reaches `changes`/`stream` and the in-process producer index only after COMMIT, so a subscriber never observes a rolled-back entry and a rolled-back producer identity stays re-emittable. Consequences: a crash before COMMIT loses the whole unit, so an attempt that had already executed re-executes on adoption (the same trade Temporal makes), and nothing that is not storage work, flow bodies, Jj snapshots, boundary prepare/settle, the lossy `flush`, may run inside the transaction. Closing this does not remove the need for idempotency keys, fencing, or compensation on external effects: no local WAL makes a remote effect atomic. The replay-convergence emits stay, because a fork's row copy and a pre-invariant database can still present a terminal row without its record |

| Time travel utilities | Replay projections, memory/SQL time-travel stores, fork, rewind, compensation, recovery, and tier-aware retry |
| Isolated (sandboxed) action execution | `EngineStore.WorkspaceSandbox` runs a sealed action's body inside a **workspace transaction**: the base is a copy-in of exactly the declared read set (Bazel's strategy, and `docs/specs/Concepts/Effect Taxonomy.md`'s strong tier, an undeclared file is not there to read), the body's writes accumulate in a path-keyed map served through both the `Workspace` tag and a re-rooted Effect `FileSystem`, and settlement is a whole-map diff. The host is untouched until `materialize`, a compare-and-set on every `beforeDigest` that applies whole or not at all; `ActionPersistence` rebases a bounded number of times on a `MaterializationConflict`. One transaction implementation serves an in-memory host (conformance, browser) and a filesystem host that retains oversized products in `@smthrs/artifacts` by digest. Queued effects are never dispatched inside the transaction, a dispatch stage runs after copy-back settles, deduplicated by idempotency key, and the journal gains `diff-bundle-captured` and `copy-back-settled`. **It is a deterministic transaction model, not a security boundary**: a body reaching the host through a service the transaction does not seed (a spawned native process) is outside it, and denying that ambient access is the VM/`SandboxProvider` story in `docs/specs/Concepts/Agent Adapters.md` |
| Whole-tree write verification | An isolated execution makes it structural: the transaction *is* the tree, so a write outside the declared set is a map comparison rather than an inference. `ActionPersistence` therefore sets `wholeTreeWritesVerified` on the boundary evidence: and, when the diff shows a deviation, records the deviation instead, with the whole-tree paths `StepBoundary.settle`'s declared-read scan could never have seen. **A sealed action with a hard boundary, run under the production filesystem composition, is now admitted to the shared step cache**; `packages/engine-store/test/SandboxedAction.test.ts` is the proof, and `examples/src/durable-layer.ts` is the composition |
