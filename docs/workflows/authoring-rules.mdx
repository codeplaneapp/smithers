---
title: Workflow authoring rules
description: The static contracts that keep authored Smithers workflows renderable and executable.
---

These rules are intentionally short and mechanical. `bunx smithers-orchestrator graph` should be the first feedback loop for a new workflow; it catches topology and schema mistakes before a run is launched.

## Reserved columns

Do not declare output fields named `runId`, `nodeId`, or `iteration`; Smithers writes those columns to every output row so it can identify the run, node, and loop pass. Input schemas must also leave `runId` reserved because the runtime supplies it. This prevents collisions between authored data and durable execution metadata. See [database reference](/reference/db#reserved-columns).

## Loops and queue-based backfill

Do not put a `<Loop>` (or `<Ralph>`) inside another loop, including through `<Sequence>`, `<Parallel>`, `<MergeQueue>`, or `<Worktree>`. The engine cannot assign a single iteration and dependency frontier to that topology, so graph extraction rejects it as `NESTED_LOOP` and names both loop ids. When per-item correction is needed, fan items into independent `<Parallel>`/`<Worktree>` lanes and put one global serialized `<MergeQueue maxConcurrency={1}>` around the landing work. Re-enter the outer loop on its next iteration to process queue failures or backfill items; do not render another loop beneath it.

## Reading loop outputs

Use `ctx.latest(outputs.review, "review")` in a loop's `until` expression: it reads the highest-iteration row for that node. For a specific cross-iteration read, use `ctx.outputMaybe(outputs.review, { nodeId: "review", iteration })`; the explicit iteration makes the dependency unambiguous. This keeps loop termination and historical reads from accidentally inspecting the current frame or an arbitrary row. See [the recipes loop pattern](/recipes#loop-output-binding).

## Production-shaped tests

Production workflow tests must load the real workflow and call `renderWorkflow` from `smithers-orchestrator/testing` with representative inputs and persisted outputs. A hand-built graph copy only proves that the test fixture is internally consistent; it cannot catch a production import, JSX, binding, or graph-extraction regression. Keep the test's output and task assertions typed, and use fake agents only at the execution boundary.

## Registering pack tests

Pack tests belong in `.smithers/tests/` and must be included by the `.smithers/package.json` `test` script (or an explicitly included test script called by it). Bun will not discover an unregistered pack test in CI, so a green local test command is not evidence that the workflow contract is covered until the file is registered.
