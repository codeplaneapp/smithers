`add` is a **system workflow** (`system: true`): internal plumbing for
Smithers' own durable processes, hidden from default listings (`workflow list` without `--system`, the interactive picker,
MCP `list_workflows`, gateway `listWorkflows`) but explicitly runnable.

`bunx smithers-orchestrator add <spec>` installs imperatively; running the workflow
instead records the same install as a durable, replayable, inspectable run.

```bash
bunx smithers-orchestrator workflow run add --input '{"spec":"user/repo"}'
```

## Input

| Field | Meaning |
| --- | --- |
| `spec` | Pack spec to install: `user/repo`, `github:user/repo[/subdir][#ref]`, `npm:pkg[@version]`, or `file:path`. |
| `global` | Install into `~/.smithers/packs` instead of the local project (default `false`). |
| `yes` | Skip the interactive trust confirmation (default `true`; workflow runs are non-interactive). |

## Stages

1. **install-pack**: deterministic (no agent), calls the CLI's `addPack` to
   fetch the spec, validate its `smithers.toon` manifest, scan imports against
   the host-provided allowlist, extract into the packs directory, and record
   the resolved version in `packs.lock.toon`.

The output row records the installed pack's name, path, scope, and trust
report. See [Workflow Catalog](/workflows/catalog) for the manifest format and
[share-pack](/workflows/share-pack) for publishing.
