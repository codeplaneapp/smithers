title: add
description: System workflow behind `bunx smithers-orchestrator add`: installs a workflow pack from GitHub, npm, or a local file as a durable, replayable run.
---

`add` is a **system workflow** (`system: true`): internal plumbing Smithers
uses for its own durable processes. It is hidden from default listings
(`workflow list` without `--system`, the interactive picker, MCP
`list_workflows`, gateway `listWorkflows`) but remains explicitly runnable.

`bunx smithers-orchestrator add <spec>` performs the installation imperatively; running the
workflow instead records the same installation as a durable run, so a pack
install can be replayed and inspected like any other Smithers process.

```bash
bunx smithers-orchestrator workflow run add --input '{"spec":"user/repo"}'
```

## Input

| Field | Meaning |
| --- | --- |
| `spec` | Pack spec to install: `user/repo`, `github:user/repo[/subdir][#ref]`, `npm:pkg[@version]`, or `file:path`. |
| `global` | Install into `~/.smithers/packs` instead of the local project (default `false`). |
| `yes` | Skip the interactive trust confirmation (default `true`; workflow runs are non-interactive). |

## Stages

1. **install-pack**: deterministic (no agent), calls the CLI's `addPack` to
   fetch the spec, validate its `smithers.toon` manifest, scan imports against
   the host-provided allowlist, extract into the packs directory, and record
   the resolved version in `packs.lock.toon`.

The output row records the installed pack's name, path, scope, and the trust
report. See the [Workflow Catalog](/workflows/catalog) for the pack manifest
format and [share-pack](/workflows/share-pack) for the publishing direction.
