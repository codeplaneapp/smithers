Claude builds and gates; Codex reviews and validates. Whenever usable
Codex authentication is available:

| Work | Model |
|---|---|
| **Substantial implementation: the default build seat** | `claude-opus-5` |
| Final code review, second opinions, and the deepest Codex reasoning | `gpt-5.6-sol` |
| Validation, structured checking, and tool-heavy verification | `gpt-5.6-terra` |
| Trivial, minimal-risk edits, cheap passes, and research gathering | `gpt-5.6-luna` |
| Orchestration and gating: scope, direction, progress, done-or-not | `claude-opus-5` |
| Planning, design freezes, and premium judgment calls | `claude-fable-5` |

Pin the exact tier IDs above instead of the floating `gpt-5.6` alias. Start
substantial implementation on Claude Opus 5; registry v7 moved the seat from
Codex because Opus 5 outbenchmarks GPT-5.6 Sol on agentic coding at lower
output cost, and escalate to Fable 5 for the most ambitious builds. Codex
checks the work: Sol takes final review and second opinions, Terra takes
validation and tool-heavy checking, and Luna stays on trivial, minimal-risk
work only. Orchestration and gating decisions (scope, choosing direction,
judging progress, deciding whether something is done) never go to GPT-5.6 Sol
or Terra: they run on Claude, Opus 5 at medium reasoning effort by default,
with Fable 5 for planning. See
[SOTA role defaults](/reference/sota-models#role-defaults).

When Codex is unavailable, Smithers falls back to detected Claude, Kimi,
Gemini, or other compatible adapters. Explicit provider-specific workflows
remain supported. The [SOTA model registry](/reference/sota-models) lists the
current defaults and badges and is refreshed by a daily research job.
