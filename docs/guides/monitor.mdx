title: The Smithers Monitor
description: A zero-setup live web UI over every run in the workspace, served by the workspace gateway at /monitor and opened with smithers monitor.
---

The Smithers Monitor is a live browser view over **every run in the workspace**: one page that groups runs by state, streams their execution trees and events, and surfaces every pending approval. It ships inside the CLI and is served by the workspace gateway at `/monitor`, so it works with no `.smithers/` pack installed and no UI code written. It is pure observation: opening it launches no run, no workflow, and no agents.

## 10-second quickstart

```bash
bunx smithers-orchestrator monitor              # open the monitor over all runs
bunx smithers-orchestrator monitor RUN_ID       # open it focused on one run
bunx smithers-orchestrator monitor --no-open    # print the URL instead of opening a browser
bunx smithers-orchestrator monitor --gateway http://127.0.0.1:7331   # use an explicit Gateway
```

The command resolves the workspace's singleton gateway the same way `bunx smithers-orchestrator ui` does (explicit `--gateway` probe, then runtime-state discovery, then the legacy port probe on `--port`, default 7331) and **autostarts** `smithers gateway` when none is running. Disable autostart with `--no-autostart`; `--no-daemon` or `SMITHERS_NO_DAEMON=1` disables daemonized autostart. It then opens the gateway's `/monitor` page in the browser, deep-linking `?runId=` when you passed a run id, and prints a `{ opened, url, gateway, runId }` envelope.

## What you see

The landing page is an operator-first surface. A grouped attention digest leads with failed runs, quota waits, and stale engines — one row per workflow and headline with a count, capped crit-first, with a View-all handoff into the runs table filter. Pending approvals live behind a bell in the topbar: its count badge escalates tone with the longest wait, and the popover holds the full approve/deny inbox so a decision stays one click from anywhere. The quiet operations strip then shows subscription windows and projected runout, workspace cost today, the shared attention count, active runs, and live engines. Subscription usage comes from `packages/usage`, the same normalized source used by `bunx smithers-orchestrator usage`.

Workspace cost today is a capped client-side sum of runs started today on this gateway. It is not a billing total. The monitor fetches a bounded recent set of run token-usage records and labels skipped, failed, and unpriced coverage instead of presenting false precision. Costs are derived from persisted `TokenUsageReported` events and scorer `modelTokenPrices`; models without a price are shown as unpriced.

The runs table shows status, progress (failed counts fold in beside done/total), ETA, start time, and duration. Selecting a run keeps every investigation surface on the same page: health, one compact identity/cost/ETA header band, recap, decisions, scores, footprint, execution tree with XML, timeline and frames, then the event log. Selecting a node mounts the inspector column at the right; without a selection the main surface keeps the full width.

The Metrics toggle is the only alternate landing branch. The runs rail, the approvals bell, URL deep links (`?runId=` and `?nodeId=`), and embed mode remain available.

On desktop the rail sits beside the main surface and the inspector appears only while a node is selected. Tablet uses an overlay inspector; phone layouts stack panels and present the inspector and approvals inbox as full-width sheets with explicit Close buttons. Tables, execution views, timelines, and event logs retain their own horizontal scrollports.

## How it relates to the other surfaces

| Surface | What it is for |
| --- | --- |
| `bunx smithers-orchestrator monitor` | Watch **all runs** live in the browser: triage, approvals, and drill-down with zero setup. |
| [`bunx smithers-orchestrator ui`](/guides/custom-workflow-ui) | Open **one workflow's own custom UI** (`.smithers/ui/<workflow>.tsx`), purpose-built for that workflow's domain. |
| `bunx smithers-orchestrator ps` / `logs` / `inspect` | The terminal watch loop: scriptable, agent-drivable, works over SSH. See the [CLI catalog](/cli/overview). |

The monitor replaced the retired `monitor` *workflow*, which had to launch a durable run of agents just to look at another run. The command observes directly through the gateway instead.
