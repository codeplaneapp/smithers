---
title: cancelRun
description: Gateway RPC for recursively cancelling a run and its whole subtree.
maturity: stable
apiVersion: v1
---

`cancelRun` cancels a run **and every transitive child-workflow descendant** as one idempotent recursive operation. `bunx smthrs cancel` and this RPC drive the same code path, so a child workflow can never outlive the parent that spawned it. Time-travel forks are spared (an independent branch of history is not a lifecycle child); continue-as-new continuations are not. Runs outside the subtree are never touched.

- Method: `cancelRun`
- Scope: `run:write`
- Transports: HTTP RPC, WebSocket RPC
- Request: `{ runId }`
- Response: `{ runId, won, status, terminalStatus?, repaired, cancellationSource?, cancelledAttempts?, descendants?, terminatedOwners?, terminatedAgents? }`

`status`, `won`, `terminalStatus`, and `repaired` describe the REQUESTED run only. `descendants` reports every other run the cascade reached as `{ runId, depth, action }`, where `action` is `cancel-requested` (a live engine will write the terminal status itself), `cancelled`, `already-terminal`, or `missing`. `cancelledAttempts` totals the attempts closed across the whole subtree. `terminatedOwners` and `terminatedAgents` list the detached owner and agent process trees that were terminated and verified gone, so no work outlives the cancelled subtree.

`status` is `cancelled`, `already-terminal`, or `not-found`. When attribution was persisted, `cancellationSource` identifies the first caller with `kind: "signal" | "rpc" | "cli" | "engine"` plus optional `detail`, `signal`, `clientPid`, `requestId`, and `clientIdentity`. Historical or unattributed cancellations omit it.

Errors are versioned as `v1` and include `InvalidRequest`, `Unauthorized`, `Forbidden`, `RunNotFound`, `RUN_NOT_ACTIVE`, and `Internal`. `RunNotFound` means no such run exists. `RUN_NOT_ACTIVE` means the run is not currently active, including already-finished runs - but only when nothing in its subtree is cancellable either, so a terminal parent with a still-live child workflow is cancelled rather than refused. `Forbidden` means the caller lacks `run:write` scope.
