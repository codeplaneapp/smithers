---
title: OpenAPI Tools
description: Generate AI SDK tools from an OpenAPI spec. Auth, filtering, observability built in.
---

`createOpenApiTools` parses an OpenAPI 3.x spec and returns AI SDK tools, one per operation, with Zod schemas converted from the spec's JSON schemas.

<Note>API reference: [OpenAPI](/reference/openapi) lists every OpenAPI export and option, and links to source and tests.</Note>

```ts
import { ToolLoopAgent } from "ai";
import { openai } from "@ai-sdk/openai";
import { createOpenApiTools } from "smithers-orchestrator/openapi";

const tools = await createOpenApiTools("./petstore.json", {
  baseUrl: "https://api.petstore.example.com",
  auth: { type: "bearer", token: process.env.PETSTORE_TOKEN! },
  include: ["listPets", "getPetById"],
  allowedOrigins: ["https://downloads.petstore.example.com"],
});

const agent = new ToolLoopAgent({
  model: openai("gpt-5.6-terra"),
  tools,
});
```

## Options

```ts
type OpenApiToolsOptions = {
  baseUrl?: string;                  // exact initial trust origin; required below
  headers?: Record<string, string>;  // requires baseUrl
  auth?:                             // requires baseUrl
    | { type: "apiKey"; name: string; in: "header" | "query"; value: string }
    | { type: "bearer"; token: string }
    | { type: "basic"; username: string; password: string };
  include?: string[];                // operationId allowlist
  exclude?: string[];                // operationId blocklist
  namePrefix?: string;               // prefix generated tool names
  allowedOrigins?: string[];         // redirect origins allowed to retain auth
  allowPrivateNetwork?: boolean;     // opt in private specs, servers, redirects
  resolveHostname?: (hostname: string) => readonly string[] | Promise<readonly string[]>;
  maxRedirects?: number;             // default: 5
  maxRequestBytes?: number;          // serialized body, default: 10 MiB
  maxResponseBytes?: number;         // default: 1 MiB
  maxSpecBytes?: number;             // remote specs, default: 5 MiB
  signal?: AbortSignal;              // cancels remote spec loading
  operations?: Record<
    string,
    | false
    | {
        include?: boolean;           // false skips this operation
        name?: string;               // agent-facing tool name
        description?: string;        // agent-facing tool description
        responseExamples?: Array<{
          status?: string | number;
          description?: string;
          value: unknown;
        }>;
      }
  >;
};
```

Pass the spec itself as the first argument to `createOpenApiTools(input,
options)`. `input` may be a parsed spec object, file path, HTTP(S) URL, or raw
OpenAPI text. The synchronous factories do not fetch URLs.

## Public API

| Export | Purpose |
|---|---|
| `createOpenApiTools(input, options?)` / `createOpenApiToolsSync(input, options?)` | Build a record of AI SDK tools keyed by operationId. |
| `createOpenApiTool(input, operationId, options?)` / `createOpenApiToolSync(...)` | Build one operation as a tool. |
| `listOperations(input)` | Return parsed operation metadata without creating tools. |
| `extractOperations(spec)` | Extract operations from an already parsed spec. |
| `loadSpecEffect(input)` | Load and parse a spec from object, path, URL, or raw text. |
| `loadSpecSync(input)` | Load and parse a spec from object, local file path, or raw text. It does not fetch URLs. |
| `jsonSchemaToZod(schema, spec, visited?, depth?)` / `buildOperationSchema(parameters, requestBody, spec)` | Lower-level schema conversion helpers. `depth` is the current recursion depth and normally remains omitted. |

`loadSpecEffect` also accepts an optional second argument with
`allowedOrigins`, `allowPrivateNetwork`, `resolveHostname`, `maxRedirects`,
`maxSpecBytes`, and `signal` for remote loads.

## CLI

Generate a reusable AI SDK tools module:

```bash
bunx smithers-orchestrator openapi generate ./api/openapi.yaml ./src/openapi-tools.js
```

The generated module imports `createOpenApiToolsSync`, creates the tools from the spec, and exports them as both `tools` and the default export.

```bash
bunx smithers-orchestrator openapi list ./api/openapi.yaml
```

`openapi list` previews every operationId, method, path, and summary. Useful for auditing what an agent will be able to call before wiring it up.

## What gets generated

For each operation:

- A Zod schema for the request body + path/query/header parameters.
- An `execute(args)` function that performs the HTTP call.
- The operation's `summary` / `description` becomes the tool description.

## Response handling

- JSON responses are parsed and returned as objects.
- Non-JSON responses are returned as strings.
- Non-2xx responses are failures, not successful tool results. The bounded body
  is included in the error detail after exact configured secret values and
  their generated Basic/query wire forms are redacted. Ordinary error fields
  remain available for recovery logic.
- Request failures, fetch failures, non-2xx responses, request/response-limit
  errors, and schema/tool execution exceptions are returned as
  `{ error: true, message, status: "failed" }` so the agent can react in its
  loop.
- Serialized operation request bodies default to a 10 MiB cap and are rejected
  locally before fetch. JSON, URL-encoded, raw, and multipart bodies are
  measured in their wire representation; multipart accounting includes
  generated boundaries and part headers. Exact-cap bodies are accepted.
- Operation response bodies default to a 1 MiB cap. An oversized declared
  length fails before reading; a streamed response is cancelled on overflow.
- Remote OpenAPI documents default to a separate 5 MiB cap. Pass `signal` in
  the factory options to cancel spec loading.
- The AI SDK tool-call `abortSignal` cancels the active request and response
  read.

## Outbound safety

OpenAPI documents are code-like input: a spec controls server URLs, paths,
header parameters, and which calls become agent tools. Audit the spec and use
`include` or per-operation curation before exposing it to an agent.

Smithers applies these network rules to generated calls:

- Remote spec URLs, resolved server URLs, operation URLs, and every redirect
  target must use HTTP(S) and cannot embed URL userinfo.
- A spec-controlled `servers[].url` is not credential trust. Configuring
  `auth` or `headers` requires an explicit `baseUrl`, which pins the exact
  initial origin (scheme, hostname, and port).
- Without `baseUrl`, a credential-free spec server is rejected when its
  hostname cannot be resolved safely or any A/AAAA answer is outside ordinary
  public-unicast space. IP literals are classified directly.
- Remote spec fetches and every redirect target use the same destination
  check. Resolution failures, empty answers, and any non-global answer fail
  closed. Redirects default to at most 5 hops, and an HTTPS-to-HTTP downgrade
  is rejected.
- `allowPrivateNetwork` deliberately permits private/special remote spec URLs,
  unpinned credential-free API servers, and redirect destinations. It cannot
  replace a credentialed `baseUrl`; redirect credentials still require the
  exact origin in `allowedOrigins`.
- Operator `auth` and `headers` override model-supplied header parameters.
  Configured auth, custom headers, declared header parameters, and query API
  keys stay on the initial origin and same-origin redirects.
- Other safe cross-origin redirects are followed after those header and query
  credentials are stripped. A redirect that would preserve a request body to
  an untrusted origin is rejected. Add the exact destination origin to
  `allowedOrigins` only when the API intentionally requires credentials there.
  Origin matching includes the scheme, hostname, and port. `allowedOrigins`
  never authorizes the initial server selected by a spec.

`allowedOrigins` is not a general destination allowlist and does not make an
untrusted spec safe. It is a narrow exception for retaining credentials across
a known cross-origin redirect.

`resolveHostname` can inject a resolver for controlled runtimes and
deterministic tests. Destination validation resolves A/AAAA records, but Fetch
resolves the hostname again when connecting; production egress policy must
still block private ranges, cloud metadata, and DNS-rebinding races.

## Filtering

`include` / `exclude` accept arrays of `operationId`. If both are set, exclude wins. Useful for limiting an agent's surface area to a specific feature ("just the inventory endpoints"). `namePrefix` prefixes generated tool names without changing the operationIds used for filtering.

Use `operations` for per-operation curation keyed by the original `operationId`. Set an entry to `false` or `{ include: false }` to skip that endpoint, set `name` to rename the generated tool, set `description` to replace the spec summary/description with agent-facing instructions, and add `responseExamples` to append concrete response shapes to the tool description. This lets a connector expose a small curated set instead of dumping every endpoint as an agent-callable tool. `include` / `exclude` still use the original `operationId`, not the curated name.

## Observability

OpenAPI tool calls update the exported Effect metrics (`openApiToolCallsTotal`, `openApiToolCallErrorsTotal`, `openApiToolDuration`) and carry Effect log annotations/spans with the operation id, method, and path. The current tool factory does not emit `OpenApiToolCalled` onto the Smithers run event bus; that event variant is typed/categorized for future event-bus integration.

## Notes / Limitations

- Schema composition (`allOf`, `anyOf`, `oneOf`) is supported; converts to Zod unions/intersections.
- Nullable fields and defaults from the spec are preserved.
- Cookie parameters are ignored when generating tool input schemas and requests.
- JSON request bodies, form-encoded bodies, multipart bodies, and raw body
  media types are encoded.
- Parameter serialization styles are not implemented. Path parameters are URL-encoded and substituted directly, and query parameters are sent with default `URLSearchParams` serialization.
- Swagger 2.0 objects are not supported as a first-class input format. Use OpenAPI 3.x specs with `openapi`, `paths`, and `info` fields.
