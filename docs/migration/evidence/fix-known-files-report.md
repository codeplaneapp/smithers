### Item D: a check verb that confined nothing (major)

#### Confirmation at the source

`packages/targets/src/Compose.ts:426` before the fix planned the check with
whatever `changes` the declaration happened to carry:

```ts
return attrs.mode === "check"
  ? GenerateCheck.call({ run: payload, changes: attrs.changes ?? [] })
  : Target.runTool(payload)
```

`checkGenerator` snapshots exactly the paths it is given, so an empty list
snapshots nothing, restores nothing, and reports no drift. The generator still
runs against the real tree. That breaks the invariant `Execute.test.ts` states
in its own header, "a checking verb does not mutate the working tree", and it
is not the parity with build system the round 1 comment claimed: build system

### Item G: a declared output inside a nested package was never confined (major)

#### Confirmation at the source

`packages/targets/src/Compose.ts:268`, in `outputPaths`:

```ts
for (const path of await Input.expandGlob(workspaceRoot, "", pattern, { signal })) paths.add(path)
```

`expandGlob` set `packageScoped: true` unconditionally
(`packages/targets/src/Input.ts:800`) and ran `crossesPackageBoundary`
unconditionally (`Input.ts:816`), which returns true as soon as a directory on
the static prefix holds a `PACKAGE.ts` (`isPackage`, `Input.ts:498-512`;
`crossesPackageBoundary`, `Input.ts:613-630`). A `changes` entry under a nested
package therefore expanded to `[]`: nothing was snapshotted, nothing compared,

### Item H: an interrupted check left the generator's output behind (minor)

#### Confirmation at the source

`checkGenerator` bracketed the spawn with `Effect.exit(Exec.run(...))` and then
called `restore(before)` as ordinary interruptible work
(`packages/targets/src/Compose.ts:340-357` before the fix). An interrupted
fiber runs no more interruptible work, so the restore never reached the disk
and the generator's bytes stayed in the tree.

#### Behavior test and the red run

`packages/targets/test/GeneratedFile.test.ts`, describe `checkGenerator`:
`restores the checked-in bytes when the check is interrupted`. The generator
writes `out.txt` then holds an interval open; the cell polls until the write
lands, then runs `Fiber.interrupt`, which completes only after the fiber's
finalizers do.

Red against the pre-fix source, load 8.12:

```
 FAIL  test/GeneratedFile.test.ts > checkGenerator > restores the checked-in bytes when the check is interrupted
AssertionError: expected 'generated\n' to be 'hand edited\n' // Object.is equality
```

#### Fix

`packages/targets/src/Compose.ts`, `checkGenerator`: the spawn-and-settle
expression is wrapped in `Effect.onInterrupt(…, () => Effect.ignore(restore(before)))`.
A finalizer runs uninterruptibly, so a cancelled `lint` leaves the checked-in
bytes behind exactly as a passing or failing one does. The finalizer reports
nothing, because the interruption is the outcome.

#### Green

Same two suites as item G, both fully passing.
