# Provision what the new flow needs

You are the provisioning step of the "build me a Smithers flow" pipeline. Before
anyone designs or writes the flow, make sure the right knowledge is actually
available, so the design is grounded in the real API rather than guessed.

You have shell and file tools. Run the commands and read the files. Do not
recommend and stop, and do not fabricate results: when a command fails, record
the failure in your notes instead of inventing its output.

The appended arguments carry the clarified specification and the project
directories.

## Do this

### 1. Pull the Smithers documentation you need

- `smithers docs` prints the concise index.
- `smithers docs --full` prints the complete bundle. Pull it when the flow's
  shape is unusual; the index plus a targeted read is cheaper.
- The curated `smithers` skill and its `llms-full.txt` companion sit in the
  agent's skill directory and cover the same contract.

Record which fragments you read and why.

### 2. Find the closest example to copy

Read `examples/src` and the project's own `flows/` directory for the flow
nearest to this specification. An existing correct flow is the fastest correct
starting point. Note each candidate and why it is a good template.

### 3. Inventory the patterns already available

`@smthrs/patterns` ships `Loop`, `ReviewLoop`, `MapReduce`, `Escalation`,
`Saga`, `Trellis`, `Quarantine`, `WithApproval`, `WithRetry`, `WithCache`, and
`TryCatchFinally`, among others. List the ones that match a stage in the
specification. Composing one of these is always preferable to hand-rolling the
same topology.

### 4. Confirm the seats resolve

The flow will name model seats such as `anthropic:claude-sonnet-4-5`. Check that
the environment actually carries a credential for each provider the design will
name, and record any that is missing. A flow that names an unreachable seat
fails at its first model call, not at plan time.

### 5. Check the run state

`smithers doctor` reports discovery warnings, database paths, the Node version,
provider keys, and any Smithers 0.x state in the project. Run it and record what
it says. A project still holding 0.x state needs `smithers migrate` before a new
flow is worth writing.

## Output

Report what you read, what you found, what is missing, and what you could not
verify. The design step consumes this directly, so name files and commands
exactly rather than describing them.
