# Persuasion Gap confirmatory study

Status: preregistered before any confirmatory task is run. The four Round 1
tasks are an explicitly labeled pilot and are excluded from confirmatory
inference.

## Question

Holding the three-stage workflow fixed, does replacing the teacher in the
implementation stage with Luna reduce final quality after the same teacher
reviews the artifact? Does changing the teacher family from Sol to Fable change
that student-replacement penalty? Secondary comparisons ask how both pipelines
perform relative to one continuous solo-teacher session.

## Benchmark and sample

The sampling frame is the official 115-task RoadmapBench train split at dataset
revision `59184e779909300a5a0150b06b945d39da81a099`: real open-source version
upgrades with hidden, target-weighted tests. The confirmatory target is 30 tasks,
ideally six from each language (C++, Go, Python, Rust, and TypeScript). The four
pilot tasks are excluded before selection.

Within each language, tasks are ranked by ascending SHA-256 of
`persuasion-gap-v1:<task_id>`. The first six whose graders pass the existing
fairness gate (oracle reward 1.0 and no-op reward below 1.0) enter the study.
Failed gates are reported and replaced by the next task in the frozen reserve
order. No result produced by an agent may influence inclusion. Before any
confirmatory agent cell ran, the machine-readable reserve list was amended from
the first ten candidates per language to the complete 111-task non-pilot frame.
The already-declared hash rule and the first ten ranks did not change; the
extension prevents multiple broken official graders from reducing the planned
sample size.

The extended validation exposed a feasibility boundary before any confirmatory
model call: only three of the first eleven Rust graders passed, with three Rust
candidates remaining. We therefore preregistered a model-blind fallback before
learning those remaining outcomes. Each language retains at least three tasks.
If a complete language frame yields fewer than six passing graders, every
passing task from that language remains in the sample and the shortfall is
filled one task per cycle from C++, Go, Python, TypeScript, then Rust, always
using the next passing task in that language's existing frozen ranking. The
cycle repeats to exactly 30 tasks. No agent output can affect this amendment.

The machine-readable candidate order is
`benchmarks/orchbench/persuasion-gap-sample.json`. The analysis is generated by
`benchmarks/orchbench/analyze_persuasion_gap.ts`, which reads only clean,
untainted, finished cells with the requested confirmatory run prefix.
`benchmarks/orchbench/verify_persuasion_gap_sample.ts` independently recomputes
the order from the pinned dataset tree and fails unless all 115 tasks and every
frozen candidate rank match.

Thirty paired tasks provide about 80% power for a two-sided paired effect of
`d_z ≈ 0.53` at unadjusted alpha 0.05, or roughly `d_z ≈ 0.57` under the
conservative 0.025 threshold for the two-test primary family. This is powered for a practically meaningful
moderate effect, not a small one. Task diversity is favored over repeated seeds
because the target estimand is performance across release tasks; one run is used
per task-condition cell. The uncontrollable sampling variance of agent CLIs is a
limitation and will be reflected in task-level confidence intervals.

RoadmapBench includes multiple releases from the same upstream projects. The
primary estimand weights release tasks equally, matching the benchmark, but
their errors may be correlated. Before any confirmatory agent cell is run, we
therefore add a project-clustered bootstrap interval and project-level sign-flip
test as a declared sensitivity analysis. It does not replace or alter the
frozen primary analysis.

## Conditions

Before any confirmatory model cell ran, design review identified that comparing
Sol→Luna→Sol only with solo Sol would confound student identity with
decomposition, handoffs, and context loss. We therefore amended the study to
add Sol→Sol→Sol and Fable→Fable→Fable controls. Further design review, still
before any confirmatory model cell, added Sol→Terra→Sol as an intermediate
student tier plus two combined-work controls: Sol plans and implements in one
session, followed by either Sol or Fable review. The planned total is therefore
270 cells. A final independent design audit, still before any confirmatory model
cell, identified that report-mediated persuasion was otherwise untestable. We
therefore added a blinded Sol-review condition, bringing the final design to
300 cells. On 2026-08-08, still before any confirmatory model cell, a further
design review identified that the blinded-review condition existed only for the
Sol teacher family: if the Luna-substitution penalty differs by teacher family
(H2), the design could not distinguish differential narrative anchoring from
differential repair ability. We therefore added condition 11,
`fable-plan-impl-review-blind` (Fable plans, Luna implements, a fresh Fable
reviews with the implementer's self-report hidden), completing the
{Sol, Fable} × {visible, blinded} factorial and adding secondary hypothesis
H4-Fable. This brings the final design to 330 cells. With eleven conditions and
thirty tasks, rotated condition order no longer balances launch positions
exactly (30 is not a multiple of 11); position remains balanced approximately
and is reported. The frozen tasks and outcomes do not change. No further
protocol amendment is permitted after the first confirmatory model cell starts.

Every included task runs in eleven conditions with the same initial checkout,
roadmap, tool policy, and hidden scorer. Within each student-replacement pair,
the graph, prompts, stage budgets, handoffs, planner, and reviewer are identical;
only the implementation-stage model changes. Agent
containers are offline. The uncredentialed post-run grader may download declared
dependencies absent from official task images; that policy is identical across
conditions, and the command/diff audit rejects answer-fetching code.
Every hidden score runs against a private disposable snapshot because official
test scripts may install, generate, or copy files into `/app`; neither checkpoint
nor final grading can alter the artifact later reviewed or audited.
The checkpoint scorer runs inside the graph; after `RunFinished`, the collector
alone invokes the final snapshot scorer. It fails the cell closed on a nonzero
exit, nonnumeric reward, or missing reward metadata.

1. `solo-sol`: Sol works end to end for up to 150 minutes.
2. `sol-sol-sol`: fresh Sol instances plan, implement, and review/fix.
3. `sol-terra-sol`: Sol plans, Terra implements, and a fresh Sol reviews/fixes.
4. `plan-impl-review`: Sol plans, Luna implements, a fresh Sol reviews and fixes.
5. `plan-impl-review-blind`: the same roles and budgets, but the reviewer is not
   given Luna's self-report and reconstructs the work from the roadmap, diff,
   repository, and tests.
6. `sol-work-sol-review`: one Sol plans and implements in a 150-minute session;
   a fresh Sol reviews/fixes for 75 minutes.
7. `sol-work-fable-review`: the same role structure, with Fable as reviewer.
8. `solo-fable`: Fable works end to end for up to 150 minutes.
9. `fable-fable-fable`: fresh Fable instances plan, implement, and review/fix.
10. `fable-plan-impl-review`: Fable plans, Luna implements, a fresh Fable reviews
    and fixes.
11. `fable-plan-impl-review-blind`: the same roles and budgets as condition 10,
    but the reviewer is not given Luna's self-report and reconstructs the work
    from the roadmap, diff, repository, and tests.

Cells run one at a time. Condition order rotates across tasks to balance
provider drift and time-of-day effects. Fallback chains are disabled. A quota
wait poisons the sample; the cell is retained in raw results but rerun once
clean under a new attempt ID, and only the clean cell enters confirmatory
analysis. Infrastructure failures and audit-tainted attempts follow the same
retain-and-rerun rule.

Before any confirmatory model call, a two-pass preflight must finish all grader
decisions and write `persuasion-gap-selected.json`: the exact 30 tasks, frozen
ordinals, upstream-project IDs, validation-receipt hashes, condition order, and
immutable Docker image references. It also contains every examined candidate's
rank, pass/invalid decision-receipt hash and reason, plus initial deficits and
overflow selections by language. The runner rejects any other task list,
condition list, round name, receipt, or image. Passing legacy markers were
upgraded only when their retained transcript contained the passing no-op/oracle
scores and the registry digest printed during that validation; two passing
markers without a recorded digest are revalidated. The receipt also binds the
dataset revision, task inputs, hidden tests, oracle patch, scorer, network
policy, and validation transcript or validator. This is an evidence migration,
not a new grader decision.

The rotation uses each frozen task ordinal, not invocation order. Every result
records its planned order and position, actual launch time, workflow hash,
protocol hash, result-schema version, validation-receipt hash, per-stage model
identifier, and agent-instance UUID. Analysis requires the exact expected model
at every agent stage, a distinct fresh UUID for every handoff, each expected
stage finishing exactly once, no unexpected stage, a clean audit, and one
workflow/protocol hash across the study. It also reconstructs the first-attempt
launch order from timestamps. These checks make labels such as “balanced” and
“fresh reviewer” auditable rather than self-asserted metadata.

There is at most one agent attempt per stage and one cell-level retry. Collection
is retried without rerunning a model; launch or collection failure prevents the
completion sentinel. A Claude quota-poisoned attempt observes a five-hour-five-
minute cooldown before its sole retry. A measured launch requires three
consecutive ten-second samples with no other running workflow or live provider
client, at least 75% CPU idle, and at most 5 MB/s disk traffic. If no clean
window appears within 30 minutes, the driver exits without launching. It also
samples provider and host contention during each cell.

## Outcomes and hypotheses

The primary outcome is official RoadmapBench Completion Score. Resolved Rate,
model wall time, and API-equivalent cost are secondary. Model wall time excludes
the added hidden checkpoint scorer so the delegated conditions are not charged
for measurement overhead; raw end-to-end wall time is also retained. Reward and
checkpoint metadata must be numeric, mutually consistent, and in `[0,1]`; a
missing reward artifact is an infrastructure failure, never an imputed zero.
Reward and cost remain valid under unrelated host load, but wall-time summaries
use only cells with no detected foreign provider client or material host pressure
during execution and show their timing-specific sample size.

For each three-stage condition, the hidden grader runs immediately after
implementation and after review. This yields a within-cell review delta.

- **H1-Sol:** `Sol→Luna→Sol − Sol→Sol→Sol < 0` on average across paired tasks.
- **H1-Terra:** `Sol→Terra→Sol − Sol→Sol→Sol < 0`; additionally report
  `Sol→Luna→Sol − Sol→Terra→Sol` to test an ordered model-tier gradient. The
  tier includes both model identity and configured reasoning effort.
- **H1-Fable:** `Fable→Luna→Fable − Fable→Fable→Fable < 0` on average.
- **H2:** the delegation penalty differs by teacher family:
  `(Fable→Luna→Fable − Fable→Fable→Fable) −
(Sol→Luna→Sol − Sol→Sol→Sol) ≠ 0`.
- **H3:** teacher review has positive mean delta over the Luna checkpoint. This
  can be true even when H1 is also true; review may help without fully recovering
  the matched all-teacher pipeline's quality.
- **H4:** showing Luna's self-report changes reviewed quality:
  `visible-report final − blinded-report final ≠ 0`. A negative estimate supports
  the persuasion-gap mechanism; a null result leaves the broader delegation
  penalty intact but does not support report-mediated anchoring.
- **H4-Fable (secondary):** the same visibility contrast under the Fable
  teacher: `Fable→Luna→Fable − Fable→Luna→Fable-blind ≠ 0`. Together with H4
  this completes the teacher × report-visibility factorial, so a
  teacher-family difference in the visibility effect (differential
  susceptibility to the implementer's narrative) is separable from a
  teacher-family difference in general repair ability.

## Analysis

The two primary tests are H1-Sol and H4; report raw and Holm-adjusted p-values
for this family. Terra, Fable, H2, H3, H4-Fable, mechanism, and operational
contrasts are prespecified secondary analyses. Report every task-level score. For paired
contrasts, report paired mean differences,
95% paired bootstrap confidence intervals, and two-sided paired permutation
p-values; directional language follows the sign of the estimate rather than a
one-sided significance test. For H3, use the same analysis on final-minus-
checkpoint deltas. Raw review delta is ceiling-confounded, so also report the
fraction of available gap closed, `(final - checkpoint) / (1 - checkpoint)`,
excluding checkpoint=1 from that ratio and reporting those ceiling cases
separately. Also report language-stratified means without significance
claims, exact win/tie/loss counts, RR, cost, and wall time.
Mechanism contrasts compare Luna's implementation checkpoint with the matched
teacher implementation checkpoint and compare weak-artifact versus
strong-artifact review deltas. Solo-teacher comparisons remain reported as
secondary operational baselines. The combined-work conditions compare a
continuous Sol plan/implementation session with the split Sol→Sol stages and
compare Sol versus Fable review. Because each condition is an independent run,
the reviewer comparison is matched by task and treatment distribution, not by
an identical frozen artifact; this adds variance but not a systematic model
advantage under balanced ordering.
As the prespecified dependence analysis, repeat each primary paired contrast
while resampling and sign-flipping whole upstream-project clusters; interpret
task-level and project-clustered results jointly. H2 has a larger approximate
minimum detectable standardized effect (`d_z ≈ 0.75`) than the primary paired
effects and is not treated as a decisive null when nonsignificant.

Reviewers never receive hidden checkpoint rewards. Cells run task-major so
within-task conditions stay as time-local as possible. Record the resolved model
identifier and date per cell; if a provider changes a model alias mid-study,
finish the current task block, report the boundary, and stratify results before
and after it rather than pooling silently.

No task is excluded for low model performance. Exclusions are limited to failed
grader fairness, audit taint, infrastructure failure, or quota poisoning, all
reported with reasons. Missing paired cells remain missing; no zero imputation.
The confirmatory conclusion is based on the frozen 30-task set after mechanical
fairness replacements and, if required, the frozen language-overflow rule—not
on the pilot.
Fewer than three valid graders in any language aborts the study rather than
silently weakening the language floor.
