`{props.migrationRoot}/{props.kernelCloneDir}`. NEVER touch the live source

Fix list from the verifier:

{`\`\`\`json
${JSON.stringify(props.fixList, null, 2)}

## What to do

1. Work through every entry in the fix list. For each, go to the named lane's
   clone or the kernel clone, apply the fix, and re-verify locally
   (build/test/lint as appropriate for that specific failure) before moving
   to the next entry.
2. Common fix categories to expect: a lane's commits not yet pushed (push the
   correct branch to the correct remote — feature branches for existing
   repos, main only for brand-new repos, never forced; verify `origin` points
   at the exact destination before pushing, never the source remote), a
   failing test (fix the code or the test), a stale link (rewrite or remove
   it), a committed manifest using `workspace:`/`file:`/`link:` specifiers
   (replace with published semver ranges), a missing/out-of-sync lockfile
   (regenerate BOTH `pnpm-lock.yaml` and `bun.lock`), a missing per-repo
   release script or one that ignores the release plan, or a version mismatch
   blocking the aggregate release dry-run (bump/pin the dependency range).
3. Do not touch lanes/repos not named in the fix list.
