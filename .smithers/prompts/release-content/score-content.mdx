## Rubric

Score against:

- factuality: 25%
- user-impact framing: 20% (sections ordered by "would a user notice and
  feel this?", each opening with the outcome, internals demoted)
- media and examples: 20% (every headline changelog section embeds a verified
  `<Frame>`; every feature with a surface has a copy-paste command or code
  block)
- specificity: 15%
- concision: 10% (no padding, no prose restating a code block, changelog
  within its 250 to 400 line target)
- template fit, positioning, and publish readiness: 10%

Rules:

- If deterministic checks include a blocker, `passed` must be false.
- If any `<!-- MEDIA GAP -->` marker remains in the changelog, `passed` must
  be false and the report must name the section needing a recording.
- If score is below minimum, `passed` must be false.
- Penalize unsupported claims, generic AI language, weak CTAs, or missing proof.
- Penalize headline sections without media, features without runnable
  examples, and implementation detail crowding out user impact.
- Prefer concrete, systems-oriented Smithers language.
