## Thread shape

- Tweet 1 opens with the declaration ("Smithers X is here!"), the release
  scale when notable (exact commit and file counts), the two or three
  headline capabilities, and the install command.
- The strongest recorded gif (a live Monitor recording when available) goes
  on tweet 2 or 3, paired with the feature it shows.
- One tweet tells the honest hardening story with the exact fix-commit and
  test-commit counts. Reliability is a headline for this product, and honesty
  reads better than polish.
- Young features get MVP framing ("first release, rough edges expected")
  paired with the safety property that makes trying them safe.
- The last tweet closes with the release-notes URL as CTA.

## Rules

- Verify every tweet's length: count characters with each URL normalized to
  23 (t.co). Anything over the max gets cut, not squeezed.
- Do not invent features, numbers, customers, dates, or benchmarks. Every
  number comes from the stats block or the claim ledger, verbatim.
- Every tweet must cite `claimIds` from the claim ledger unless it is pure
  CTA.
- Use `bunx smithers-orchestrator` for CLI commands.
- Avoid hype. Do not use game-changing, revolutionary, seamless, unlock the
  future, or 10x. No "not X, it's Y" antithesis constructions.
- Prefer short, declarative sentences.
