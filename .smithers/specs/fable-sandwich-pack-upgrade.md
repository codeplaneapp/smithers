# Fable-sandwich upgrade of the `smithers init` workflow pack

Synthesized from a 36-agent audit (one Fable auditor per pack workflow + shared
components + agents scaffold), 2026-07-02/03. Goal: put every seeded/legacy pack
workflow on the **fable sandwich** and improve orchestration (panels,
backpressure, budgets) without breaking frozen UI/schema contracts.

## The doctrine (model → role)

- **`claude-fable-5`** — senior engineer. Heavy planning, architecture, final /
  critical review, high-stakes synthesis & verdicts, failure diagnosis, reports.
  The bread on both ends. Never trivial tool calls.
- **`claude-opus-4-8`** — junior/mid Claude; secondary smart seat; always-present
  fallback behind fable in chains.
- **Codex `gpt-5.5`** (`CodexAgent`, `skipGitRepoCheck:true`) — mid engineer:
  implementation, validation, review-fix; also the model-diverse second panel
  seat (different blind spots than Claude). `xhigh` for multi-file refactors.
- **Gemini `gemini-3.1-pro-preview`** (`AntigravityAgent`, CLI probe `agy`) —
  frontend / cheap large-context reader (sweeps, log/file reading). The legacy
  `GeminiAgent` / `gemini` CLI is **sunset** — never propose it.
- **`claude-sonnet-5`** + **Kimi** — interns: mechanical tool calls, glue,
  formatting, reporting. `claude-sonnet-5` is the guaranteed implementer
  fallback. **Kimi stays out of default chains** (its auth-setup error is
  non-retryable and kills the run instead of failing over).
- Purge-on-sight stale ids: `claude-sonnet-4-6`, `claude-sonnet-4-7`,
  `claude-sonnet-4-20250514` → `claude-sonnet-5`.

Availability constraint: CI and fresh machines may have **no agent CLIs** (or
only claude). Structure/graph-render must never depend on a CLI: use tier pools
(`agents.*`) or the `roles.ts` probe+static-fallback pattern.

## Two agent-provisioning systems (load-bearing)

1. **`.smithers/agents.ts`** — the tier pools (`cheapFast`/`smart`/`smartTool`/
   `review`/**`planning`**/**`implement`**) that MOST workflows import via
   `../agents`. Generated by `apps/cli/src/agent-detection.js`
   (`generateAgentsTs` detection path + `generateAccountsAgentsTs` accounts
   path). Regenerated on every `smithers init`, so a workflow + its pools ship
   version-locked.
2. **`.smithers/components/roles.ts`** — self-contained role registry
   (`implementer`/`panelists`/`synthesizer`/`polishReviewer`) used by the
   plan-implement family (`Review`/`PlanPanel`/`ValidationLoop`). Probe-guarded,
   CI-safe. Mirrored byte-for-byte into the `renderComponents` string embed in
   `workflow-pack.js` (no drift gate — mirror by hand).

## Frozen contracts (do not break)

- Workflow id, input schema, output channel schemas, and every **node id** the
  UI (`.smithers/ui/<id>.tsx`, `apps/cli/src/workflowUiSources.js`) or docs read.
  Model choice is NOT part of the contract — re-tiering agents is safe.
- **Legacy** workflows ship from a string embed in `workflow-pack.js`
  (`renderWorkflowFile`); `.smithers/workflows/<id>.tsx` is the canonical dogfood
  copy. Any legacy edit must touch **both** and be mirrored exactly.
- **Seeded** workflows ship verbatim from `.smithers/workflows/<id>.tsx` via
  `scripts/generate-workflow-pack.ts` → `seeded-workflow-pack.generated.js`
  (regen after every edit). No embed twin — single-file edits.
- `hello` stays minimal; `init`/`post-failure` are system workflows, reliability
  over cleverness.
